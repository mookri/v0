## Objective

Tenants are provisioned and maintained declaratively: a validated, versioned tenant blueprint describes desired state (entitled modules, configuration classes, feature intent, hierarchy/working-context defaults), a reconcile loop drives observed state toward desired idempotently and convergently, and the provisioning pipeline is resumable with idempotency keys and named failure/recovery semantics.

## Scope

**In scope:**

- Blueprint schema + validation + versioning; desired-vs-observed diff computation
- Reconcile loop (idempotent, convergent, bounded per-module failure isolation)
- Provisioning pipeline stages with idempotency keys, resume, and recovery
- Control-plane events + status endpoints; reconciliation verification suite (CTRL-018)

**Out of scope:**

- Plan catalog commercial decisions (product owns plan definitions) — owned by Product baseline PROD register
- Module implementation work — the pipeline installs modules, it does not build them — owned by Phase tasks

## Acceptance criteria

1. **AC-T-0K03-01-1** — Blueprint validation rejects blueprints containing modules not entitled by the tenant's plan, unknown configuration classes, or invalid feature intent — each with a named error code referencing CTRL-006 rules.
2. **AC-T-0K03-01-2** — The reconcile loop is idempotent and convergent: GIVEN a drifted observed state WHEN reconcile runs twice THEN the second run is a no-op and the desired-vs-observed diff is empty (CTRL-009/018).
3. **AC-T-0K03-01-3** — The provisioning pipeline is resumable: GIVEN a failed stage WHEN the run is retried with the same idempotency key THEN completed stages are not re-executed and no duplicate schema, seed data, or module installs result (CTRL-011/012).
4. **AC-T-0K03-01-4** — Events `control_plane.provisioning.stage_completed|failed` and `control_plane.reconcile.drift_detected` are emitted per CTRL-019 with run correlation ids.
5. **AC-T-0K03-01-5** — Provisioning and reconcile status endpoints under `/api/v1/control-plane` expose run state to holders of `platform:provisioning:view` and return 403 otherwise.
6. **AC-T-0K03-01-6** — GIVEN a principal lacking `platform:provisioning:view` / `platform:provisioning:execute` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-0K03-01-7** — Tenant isolation holds: every new table (`tenant_blueprints`, `blueprint_versions`, `provisioning_runs`, `reconciliation_logs`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-0K03-01-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
