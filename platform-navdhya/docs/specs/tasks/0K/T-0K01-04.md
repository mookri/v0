## Objective

Time-boxed, revocable delegation grants let a grantor lend a subset of their capabilities to a delegatee for a bounded window. Grants are SoD-checked at grant time, intersected with the grantor's live authority, recorded with delegation origin in the decision log, and expire or revoke without grace windows.

## Scope

**In scope:**

- Delegation grant records (grantor, delegatee, capability subset, `expires_at`, status)
- SoD conflict check at grant time; chain consumption of active delegations (augmentation stage)
- Grant/revoke endpoints + expiry sweep; delegation origin in decision-log entries

**Out of scope:**

- Open-ended or transitive multi-hop delegation — prohibited by design (ADR-0017)
- Delegation of `sensitive`-flagged capabilities without step-up — blocked

## Acceptance criteria

1. **AC-T-0K01-04-1** — Endpoint `POST /api/v1/delegations` returns 201 with a bounded `expires_at` for valid grants and 422 `validation_failed` when `expires_at` is missing (no open-ended delegations) or the capability set exceeds the grantor's authority.
2. **AC-T-0K01-04-2** — GIVEN an active delegation WHEN the delegatee exercises a delegated capability THEN the decision log records delegation origin (grantor, grant id) and the effective authority is the intersection of the grantor's live authority and the delegation scope.
3. **AC-T-0K01-04-3** — GIVEN a delegation that has expired, been revoked, or whose grantor lost the capability WHEN the delegatee requests it THEN the request is denied from the next request cycle with no grace window.
4. **AC-T-0K01-04-4** — Delegation grants that would create an SoD conflict are rejected at grant time with the conflicting rule named in the error envelope.
5. **AC-T-0K01-04-5** — Events `platform.delegation.granted|revoked|expired` are emitted with grant metadata and correlation ids.
6. **AC-T-0K01-04-6** — GIVEN a principal lacking `platform:delegation:grant` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-0K01-04-7** — Tenant isolation holds: every new table (`delegation_grants`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-0K01-04-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
