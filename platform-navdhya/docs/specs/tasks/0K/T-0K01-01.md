## Objective

Make capabilities parsed, structured data and introduce policies as first-class records. After this task every capability code resolves to module/resource/action metadata (version, sensitive flag), policies can be declared with effect, capability selector, scope bindings, conditions, and priority, and role assignments carry scope bindings — the schema foundation the evaluation engine builds on.

## Scope

**In scope:**

- Migrations for `policies`, `capability_metadata` (parse columns on the permission registry), and `role_scope_bindings`
- Capability parser for `<module>:<resource>:<action>` codes (open per-module action vocabulary, `sensitive` flag, version)
- Policy validation rules (effect, selector shape, condition schema, priority)
- Policy CRUD admin endpoints + `platform:sync-permissions` parse/validate integration

**Out of scope:**

- Policy evaluation and the explicit-DENY precedence chain — owned by [T-0K01-02](./T-0K01-02.md)
- Delegation grants — owned by [T-0K01-04](./T-0K01-04.md)
- Decision logging and AI-agent safety — owned by [T-0K01-03](./T-0K01-03.md)

## Acceptance criteria

1. **AC-T-0K01-01-1** — GIVEN the 0K migrations have run WHEN `platform:sync-permissions` executes THEN every manifest-declared capability is parsed into structured metadata and any malformed code aborts the sync with a named error code.
2. **AC-T-0K01-01-2** — Endpoint `POST /api/v1/policies` returns 201 with the policy envelope for a valid payload and 422 with `validation_failed` when effect, capability selector, or condition schema is invalid.
3. **AC-T-0K01-01-3** — Event `platform.policy.created` (and `.updated` / `.status_changed`) is emitted with the full policy selector payload when a policy record changes.
4. **AC-T-0K01-01-4** — GIVEN a principal lacking `platform:policy:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
5. **AC-T-0K01-01-5** — Tenant isolation holds: every new table (`policies`, `capability_metadata`, `role_scope_bindings`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
6. **AC-T-0K01-01-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
