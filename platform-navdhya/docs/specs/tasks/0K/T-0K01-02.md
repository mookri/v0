## Objective

Authorization decisions evaluate the deterministic SEC-022 chain — explicit DENY, security constraints (SoD, membership/tenant state, licensing), delegation augmentation, capability grants, policy allow/deny — ending in default deny. The chain is wired into the kernel authorization middleware so every route and contract call passes through it, with per-(principal, capability, context) decision caching invalidated on grant/policy change.

## Scope

**In scope:**

- Chain evaluator implementing the SEC-022 precedence order with stage attribution
- Integration with effective-authority computation (scopes ∩ grants ∩ membership ∩ policies)
- Decision cache with invalidation on grant/policy/SoD changes
- Restricted explain endpoint + CLI for debugging decisions

**Out of scope:**

- Decision log persistence and sampling — owned by [T-0K01-03](./T-0K01-03.md)
- Delegation grant records (the chain consumes delegation state once it exists) — owned by [T-0K01-04](./T-0K01-04.md)

## Acceptance criteria

1. **AC-T-0K01-02-1** — GIVEN a matching explicit `deny` policy and a matching allow grant WHEN the capability is evaluated THEN the decision is DENY with deciding stage `explicit_deny` (DENY always wins regardless of grant source).
2. **AC-T-0K01-02-2** — GIVEN no matching grant or policy WHEN the capability is evaluated THEN the decision is DENY with deciding stage `default_deny` (fail-closed).
3. **AC-T-0K01-02-3** — Evaluation is deterministic: identical (principal, capability, resource, context) inputs yield identical decision + stage across repeated calls, and cached results are invalidated within one request cycle of any grant, policy, or SoD change.
4. **AC-T-0K01-02-4** — Endpoint `GET /api/v1/authz/explain` returns the full chain trace for principals visible to the caller and 403 with envelope code `authorization_denied` otherwise.
5. **AC-T-0K01-02-5** — GIVEN a principal lacking `platform:authz:explain` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-0K01-02-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
