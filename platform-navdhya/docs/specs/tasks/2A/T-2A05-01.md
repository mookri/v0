## Objective

Structured extension data lands on standard resources as metafields: platform-managed definitions (namespace, key, type, validations, optional indexed slot) validated on write, values stored in the ecosystem's shared column-slot + JSON-overflow model (no per-tenant schema migrations), and additive `meta_fields` output on host-resource API responses. This is the restricted v1 preview of the Phase 5 custom-fields engine.

## Scope

**In scope:**

- Metafield definition records (platform-managed: seeded + operator-extensible) with the registered type vocabulary (`string|integer|decimal|boolean|date|datetime|json|reference`)
- Value storage on the ecosystem storage model (`custom_field_values` typed columns + JSON overflow, indexed slots)
- Definition-validated writes; values readable/writable only with the host resource's `update` permission
- Additive `meta_fields` block on API responses for the v1 host resources (`catalog:product`, `catalog:variant`, `customers:customer`, `sales:order`, `store:store`, `content:page`, `content:article`)

**Out of scope:**

- Tenant self-service definition management (Phase 5 custom objects) — owned by P5 roadmap
- Metaobjects (definition-bound records) — owned by [T-2A05-02](./T-2A05-02.md)

## Acceptance criteria

1. **AC-T-2A05-01-1** — Metafield values are definition-validated: GIVEN a definition of type `integer` WHEN a non-numeric value is written THEN the request is rejected with a named validation code; valid values persist in the typed column with JSON overflow for oversized payloads.
2. **AC-T-2A05-01-2** — Authorization inheritance holds: writing a metafield on a host resource requires the host's `update` permission; a principal with `view` only gets the values in responses but 403 on writes (negative path asserted per host resource).
3. **AC-T-2A05-01-3** — API responses of the seven v1 host resources carry metafield values additively under `meta_fields`; resources without values return an empty block — never a changed base shape (additive-rule contract test).
4. **AC-T-2A05-01-4** — Event `content.metafield_def.updated` is emitted on definition create/update with namespace + key identifiers.
5. **AC-T-2A05-01-5** — GIVEN a principal lacking `content:metafield:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A05-01-6** — Tenant isolation holds: every new table (`custom_field_values`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A05-01-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
