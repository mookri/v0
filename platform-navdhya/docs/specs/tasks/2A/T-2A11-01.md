## Objective

Listing-channel product feeds are generated declaratively: `feed_definitions` (code google|meta|custom, field_map JSON, filter JSON, schedule) drive a queued generation job composing from storefront projections + market prices into a versioned kernel Files artifact, exposed via a public endpoint that 302s to a signed, edge-cached file URL. Feed rows exclude unpublished/hidden products, include availability state, and regenerate on catalog/availability/price events plus schedule.

## Scope

**In scope:**

- `feed_definitions` entity + CRUD under the store discovery surface
- Queued generation job (storefront_products + storefront_inventory_views + market prices when a market is bound)
- Versioned file artifacts (kernel Files) + public signed-URL endpoint with edge caching
- Regeneration triggers: `store.product.*`, `store.availability.changed`, `markets.price_rule.updated`, schedule

**Out of scope:**

- Channel API push integrations (feeds are pull-based files) — owned by Deferred
- Feed submission management to external platforms — owned by Out of scope v1

## Acceptance criteria

1. **AC-T-2A11-01-1** — Feed composition exclusions hold: unpublished and hidden products never appear in any feed; availability state is always included, and out-of-stock rows follow the feed template's policy (include-with-flag default).
2. **AC-T-2A11-01-2** — Generation produces a versioned file artifact in kernel Files; the public endpoint `GET /api/v1/public/stores/{slug}/feeds/{code}` responds 302 to the signed file URL with edge caching — no dynamic row-by-row rendering on the public path.
3. **AC-T-2A11-01-3** — Regeneration triggers fire on `store.product.*`, `store.availability.changed`, `markets.price_rule.updated`, and the definition's schedule; concurrent triggers coalesce into one generation run (debounce asserted).
4. **AC-T-2A11-01-4** — Public feed endpoints are on the CI-pinned public allowlist; market-bound feeds resolve prices through `MarketPriceResolver` (never raw projection reads).
5. **AC-T-2A11-01-5** — GIVEN a principal lacking `store:feed:view` / `store:feed:create` / `store:feed:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A11-01-6** — Tenant isolation holds: every new table (`feed_definitions`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A11-01-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
