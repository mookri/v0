## Objective

Storefront SEO infrastructure ships: XML sitemaps generated from published products/collections/pages/articles with `lastmod` from projection timestamps (max 50k URLs per file behind a sitemap index, regenerated on content publish + daily), and URL redirect management via `storefront_redirects` — including automatic 301 insertion on handle changes — resolved at the storefront edge before content fetch.

## Scope

**In scope:**

- Sitemap generation endpoint (`/public/stores/{slug}/sitemap.xml` + per-section splits + index)
- `storefront_redirects` entity (from_path UQ per store, to_path, kind 301|302, status) + CRUD
- Auto-301 listener on handle changes (`store.product.published` / content publish with handle diff)
- Edge resolution: lookup miss → normal routing; hit → redirect before content fetch

**Out of scope:**

- Redirect import/bulk tooling — owned by Deferred
- Sitemap ping/submission to crawlers — owned by Out of scope v1

## Acceptance criteria

1. **AC-T-2A11-02-1** — Sitemaps include only published products/collections/pages/articles with `lastmod` from projection timestamps; files cap at 50k URLs with a sitemap index, and regeneration runs on content publish events plus the daily schedule.
2. **AC-T-2A11-02-2** — Handle changes auto-insert a 301 from the old handle: GIVEN a product republished with a new handle WHEN the publish event carries the handle diff THEN a `storefront_redirects` row (301) exists before the next edge resolution.
3. **AC-T-2A11-02-3** — Edge resolution order holds: redirect hit resolves before content fetch (no content lookup cost on hits); lookup miss falls through to normal routing; redirect chains are validated cycle-free on write.
4. **AC-T-2A11-02-4** — Sitemap public endpoints are on the CI-pinned public allowlist; redirect CRUD enforces `store:redirect:view|create|update` with cross-store denial fail-closed.
5. **AC-T-2A11-02-5** — GIVEN a principal lacking `store:redirect:view` / `store:redirect:create` / `store:redirect:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A11-02-6** — Tenant isolation holds: every new table (`storefront_redirects`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A11-02-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
