## Objective

Orders carry staff annotations and classification data: notes with internal/customer visibility, tags mirrored onto the order for filtering, and structured attributes — all audited and editable post-placement without touching order totals or state.

## Scope

**In scope:**

- `order_notes` with visibility (`internal|customer`) and author membership
- `order_tags` mirrored to `sales_orders.tags` (additive column)
- Notes/tags API under the order-ops surface; customer-visible notes surface in buyer order view and invoice-link pages

**Out of scope:**

- Customer-facing notes on customers records — owned by [T-2A04-06](./T-2A04-06.md)
- Tag-driven automation rules — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-2A02-03-1** — Notes with `visibility=internal` never appear in buyer-facing responses (invoice-link pages, buyer order view); `customer` notes do — enforced by response-shape tests, not just policy.
2. **AC-T-2A02-03-2** — Tag writes stay consistent: every `order_tags` change mirrors into `sales_orders.tags` in the same transaction; a consistency assertion runs in the feature suite.
3. **AC-T-2A02-03-3** — Note and tag mutations are audited with actor + order reference (audit coverage per DoD item 5).
4. **AC-T-2A02-03-4** — GIVEN a principal lacking `order_ops:note:view` / `order_ops:note:create` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
5. **AC-T-2A02-03-5** — Tenant isolation holds: every new table (`order_notes`, `order_tags`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
6. **AC-T-2A02-03-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
