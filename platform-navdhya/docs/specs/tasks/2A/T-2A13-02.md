## Objective

The v1 importer/exporter matrix ships on the shared job surface: every row of the registered table (catalog, customers incl. orders export, pricing, markets, content translations, inventory) is a declarative mapping registered in its module's provider with column validators and row handlers — no module ships an ad-hoc parser. Every importer replays idempotently and every exporter produces a tenant-scoped signed artifact.

## Scope

**In scope:**

- Six module mapping registrations per the v1 matrix (import and/or export as registered)
- Column validators + row handlers per resource; error reporting through `data_job_errors`
- Orders export for customers (SH-056) with buyer/admin scope guards
- All-or-nothing declaration for stock-level adjustments (inventory safety)

**Out of scope:**

- Resources beyond the v1 matrix — owned by Post-v1 roadmap
- Scheduled/recurring exports — owned by Deferred seam

## Acceptance criteria

1. **AC-T-2A13-02-1** — Every matrix row round-trips: importing a valid fixture file and exporting the same resource yields semantically equivalent data (round-trip fixture tests per row); malformed rows land in `data_job_errors` with row numbers and codes.
2. **AC-T-2A13-02-2** — Inventory stock-level imports declare all-or-nothing: any invalid row aborts the whole adjustment with no partial stock changes (safety invariant asserted under failure injection).
3. **AC-T-2A13-02-3** — The customers orders export respects effective authority: the exported rows never exceed the requester's org visibility (scope-guard test with mixed-scope principals).
4. **AC-T-2A13-02-4** — Importers replay idempotently on the shared surface: same file + key returns the stored result for every matrix row (K-023 pattern, asserted per importer).
5. **AC-T-2A13-02-5** — GIVEN a principal lacking `data_tools:job:create` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A13-02-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
