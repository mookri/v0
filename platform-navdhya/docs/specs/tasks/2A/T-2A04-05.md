## Objective

Duplicate customer records merge irreversibly under a sensitive, ACR-2-gated operation: references re-point via events + contracts (contacts/addresses, buyer profile follows survivor, credit balances summed via a merge ledger line, wishlists unioned with variant dedupe), the merged record is archived with a `merged_into` marker, and `customer_merge_log` records the field map at audit grade.

## Scope

**In scope:**

- `POST /api/v1/customer-accounts/merges` (sensitive, ACR 2) with survivor selection validation
- Reference re-pointing flows (contacts/addresses, orders keep historical ids, buyer profile follows survivor)
- Credit balance summation via merge ledger line; wishlist union with dedupe
- `customer_merge_log` audit record + archive marker; irreversibility rule

**Out of scope:**

- Merge undo (corrections are a second merge in the other direction) — owned by By design
- Merging across tenants — prohibited — owned by By design

## Acceptance criteria

1. **AC-T-2A04-05-1** — GIVEN two customers of the same tenant WHEN merge executes THEN contacts/addresses re-point to the survivor, the buyer profile link follows the survivor, credit balances are summed into one ledger (merge line kind), wishlists are unioned with variant dedupe, and the merged customer is archived with a `merged_into` marker.
2. **AC-T-2A04-05-2** — Merge is irreversible: no code path edits `customer_merge_log` or resurrects the merged record; corrections create a new merge in the opposite direction (asserted by review + test).
3. **AC-T-2A04-05-3** — `POST /customer-accounts/merges` requires `customers:customer:update` + `customer_accounts:merge:execute` with ACR 2; merging customers from different tenants returns 422 with a named code.
4. **AC-T-2A04-05-4** — Event `customer_accounts.customer.merged` is emitted with surviving + merged customer references and the log id.
5. **AC-T-2A04-05-5** — GIVEN a principal lacking `customer_accounts:merge:execute` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A04-05-6** — Tenant isolation holds: every new table (`customer_merge_log`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A04-05-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
