## Objective

Storefront strings are translatable at the storage layer: `content_translations` keyed by (tenant, locale, namespace, key) with namespaces for storefront/product/page/article/menu, a read API resolving the request locale with store-locale fallback, and bulk import/export through the data-tools surface. Editing tooling and auto-translation remain post-v1.

## Scope

**In scope:**

- `content_translations` storage (locale, namespace, key, value; UQ per tenant)
- Locale resolution on storefront responses (`Accept-Language` / `?locale=` with store-locale fallback)
- Translations CRUD under the content surface; bulk import/export wired to T-2A13-02's importer set

**Out of scope:**

- Translation editing tooling + auto-translation — owned by Deferred (planning DF-11)
- Locale negotiation for admin console — owned by Admin stays single-locale in v1

## Acceptance criteria

1. **AC-T-2A05-04-1** — Translation keys are unique per (tenant, locale, namespace, key); upsert semantics apply on import (same key replaces value with audit, never duplicates).
2. **AC-T-2A05-04-2** — Locale resolution holds: requests with `?locale=fr` resolve French strings where present, missing keys fall back to the store locale, and unknown locales fall back without error (fallback chain asserted).
3. **AC-T-2A05-04-3** — Event `content.translation.updated` is emitted on create/update with locale + namespace + key identifiers.
4. **AC-T-2A05-04-4** — GIVEN a principal lacking `content:translation:view` / `content:translation:create` / `content:translation:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
5. **AC-T-2A05-04-5** — Tenant isolation holds: every new table (`content_translations`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
6. **AC-T-2A05-04-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
