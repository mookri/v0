## Objective

One kernel-backed job surface serves every module's import/export/bulk needs: `data_jobs` + `data_job_errors` with declarative module-registered mappings, queued workers on kernel Jobs, progress rows + result files on kernel Files, completion notifications + events. Imports carry client idempotency keys (replay returns the stored result), failures are per-row unless all-or-nothing is declared, and limits (100k rows / 50 MB) reject oversized jobs fail-fast.

## Scope

**In scope:**

- `data_jobs` (kind import|export|bulk_update, module_code, resource, status machine, totals, idempotency_key) + `data_job_errors`
- Declarative mapping registry (resource, columns, validators, row handler) in module providers — no ad-hoc parsers
- Queued worker pipeline: progress rows, result files, completion notification + event
- Idempotent replay, per-row vs all-or-nothing atomicity, limits enforcement, authorization via target resource permissions + tenant-scoped signed result URLs

**Out of scope:**

- Concrete importers/exporters (the v1 matrix) — owned by [T-2A13-02](./T-2A13-02.md)
- Streaming/async progress push (polling v1) — owned by Deferred

## Acceptance criteria

1. **AC-T-2A13-01-1** — Idempotency holds: re-uploading the same file with the same client key replays the stored result (no second job runs), per the API idempotency pattern (K-023).
2. **AC-T-2A13-01-2** — Atomicity modes hold: per-row importers collect failures into `data_job_errors` with row numbers and complete with an error report; importers declaring all-or-nothing roll back entirely on any row failure.
3. **AC-T-2A13-01-3** — Limits enforce fail-fast: files over 50 MB or jobs over 100k rows reject with 422 `data_tools_limit_exceeded` before queueing.
4. **AC-T-2A13-01-4** — Job creation requires the target resource's `create` (imports) / `export` (exports) permission; result files are served as tenant-scoped signed URLs — cross-tenant job access returns 403/404 fail-closed.
5. **AC-T-2A13-01-5** — Events `data_tools.job.completed` / `.failed` are emitted with job + totals references; completion notifications carry the result file reference.
6. **AC-T-2A13-01-6** — GIVEN a principal lacking `data_tools:job:view` / `data_tools:job:create` / `data_tools:job:cancel` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-2A13-01-7** — Tenant isolation holds: every new table (`data_jobs`, `data_job_errors`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-2A13-01-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
