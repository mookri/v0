## Objective

Digital products sell and deliver without stock or shipping: `products.type=digital` variants reference `digital_assets` (kernel Files, download limit, link TTL), skip inventory reservation and the checkout shipping step, and fulfill via single-use-counted signed download URLs triggered by `sales.order.fulfilled` (or auto-fulfill per store setting). Expired/exhausted links return 410 and buyers can request rate-limited re-issue.

## Scope

**In scope:**

- `digital_assets` entity + product type wiring (reservation skip, shipping-step skip for all-digital carts)
- Delivery listener on `sales.order.fulfilled`: signed URL generation honoring `download_limit` + `link_ttl_days` (kernel counters)
- Buyer notification with links + links in the buyer order view; re-issue self-service (rate-limited, audited)
- Store setting `store.digital_auto_fulfill`

**Out of scope:**

- Streaming/licensed content delivery — owned by Deferred
- DRM enforcement — owned by Out of scope v1

## Acceptance criteria

1. **AC-T-2A06-03-1** — Digital variants reserve no stock and all-digital carts skip the shipping step: checkout completes without a shipping address when every line is digital (feature test).
2. **AC-T-2A06-03-2** — Download links are single-use-counted: GIVEN `download_limit=3` WHEN the link is used a fourth time THEN the request returns 410 `files_link_expired`; expired TTL behaves identically.
3. **AC-T-2A06-03-3** — Re-issue is rate-limited and audited: a buyer's re-issue request beyond the configured window rejects, and every re-issue writes an audit record.
4. **AC-T-2A06-03-4** — Events `catalog.digital.delivery_sent` (and the registered expiry/re-issue events) are emitted with order + line references — never the signed URLs themselves.
5. **AC-T-2A06-03-5** — GIVEN a principal lacking `catalog:product:view` / `catalog:product:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A06-03-6** — Tenant isolation holds: every new table (`digital_assets`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A06-03-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
