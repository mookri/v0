## Objective

Buyers register and authenticate on kernel identity (not a parallel buyer database): a `buyer_profiles` record binds 1:1 to a kernel user per tenant, optionally links to a `customers` record, and carries default address, marketing opt-in, and locale. The storefront auth wall gates buyer-only surfaces, and buyer self-service scopes are restricted to buyer clients only.

## Scope

**In scope:**

- `buyer_profiles` entity (user_id UQ, customer_id NULL, default_address_id, marketing_opt_in, locale)
- Registration/login wiring on kernel identity + buyer OAuth client profile (ADR-0005)
- Auth wall on buyer-account routes; profile CRUD self-service endpoints under `/api/v1/customer-accounts`
- Buyer scope restriction: self-service tokens can only access buyer surfaces

**Out of scope:**

- Admin-side customer master data (customers module) — owned by Phase 1 customers baseline
- Order history and reorder — owned by [T-2A04-02](./T-2A04-02.md)

## Acceptance criteria

1. **AC-T-2A04-01-1** — One kernel user maps to exactly one buyer profile per tenant (UQ on user_id scoped by tenant); registration creates user + profile transactionally.
2. **AC-T-2A04-01-2** — Buyer self-service tokens (buyer client profile) cannot access admin surfaces: requests to admin routes return 403 with `authorization_denied` even when the underlying user holds a membership (scope restriction asserted).
3. **AC-T-2A04-01-3** — Profile endpoints return the caller's own profile only; accessing another buyer's profile returns 403 (fail-closed, no enumeration).
4. **AC-T-2A04-01-4** — Events `customer_accounts.profile.created` / `.updated` are emitted with profile references on registration and self-service updates.
5. **AC-T-2A04-01-5** — GIVEN a principal lacking `customer_accounts:profile:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A04-01-6** — Tenant isolation holds: every new table (`buyer_profiles`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A04-01-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
