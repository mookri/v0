## Objective

Shopify-class selling plans generalize subscriptions: `selling_plans` (kind subscription|preorder|trial, billing + pricing + availability JSON) with buyer self-service policies, preorder capacity tracking via atomic committed-quantity increments, and trial plans creating `trialing` subscriptions converted by the existing renewal scheduler. The Phase 2 subscriptions module is extended additively — existing entities and state machine unchanged.

## Scope

**In scope:**

- `selling_plans`, `selling_plan_policies` (cancel/pause/swap/reschedule), `preorder_reservations` entities
- Additive `subscriptions.selling_plan_id` with 1:1 backfill for existing rows
- Preorder mechanics: pricing kinds (`full_prepay`, `deposit_then_balance` via order_ops schedules), atomic commit at capture, FIFO allocation on stock receipt, shortfall alerting
- Trial mechanics: `trialing` state entry + first billing at trial end via existing renewal path
- Storefront exposure: eligible plans on the public product endpoint (additive `selling_plans` field)

**Out of scope:**

- Plan-per-variant pricing customizations beyond availability JSON — owned by Deferred
- Subscription swap flows beyond the policy flags — owned by Phase 2 subscriptions baseline

## Acceptance criteria

1. **AC-T-2A07-01-1** — Preorder commit holds: GIVEN a preorder plan with `reserved_qty_limit` WHEN capture succeeds THEN `preorder_reservations.committed_qty` increments atomically (row-lock pattern); exceeding the limit returns 409 `selling_plan_capacity_reached`.
2. **AC-T-2A07-01-2** — Preorder pricing kinds hold: `full_prepay` captures the full amount at checkout; `deposit_then_balance` creates a payment schedule via the order_ops deposit machinery — no third money flow exists.
3. **AC-T-2A07-01-3** — Allocation serves committed preorders FIFO by capture time when stock receipts arrive; oversell beyond receipts emits the shortfall event with an ops alert, and the subscriptions state machine for pre-existing rows is unchanged (regression suite green).
4. **AC-T-2A07-01-4** — Trial plans create subscriptions in `trialing` with the first billing attempt at trial end through the existing renewal scheduler path — no new money flow.
5. **AC-T-2A07-01-5** — Events `subscriptions.selling_plan.created` / `.updated` / `.activated` / `.archived` and `subscriptions.preorder.committed` / `.shortfall` are emitted with plan + variant references.
6. **AC-T-2A07-01-6** — GIVEN a principal lacking `subscriptions:selling_plan:view` / `subscriptions:selling_plan:create` / `subscriptions:selling_plan:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-2A07-01-7** — Tenant isolation holds: every new table (`selling_plans`, `selling_plan_policies`, `preorder_reservations`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-2A07-01-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
