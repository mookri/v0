## Objective

Reusable structured content ships as metaobjects: named definitions whose field sets are metafield definitions, and records validated against them with unique handles per tenant. Records are tenant-scoped, audited, searchable through the kernel Search service, referenceable from metafields (`type=reference`), and served read-only on the public storefront API when published.

## Scope

**In scope:**

- `metaobject_definitions` (code UQ, field_defs JSON) + `metaobject_records` (definition_code, handle UQ per tenant, validated fields JSON, published_at)
- Definition/record CRUD + `:publish` under the content surface
- Public read endpoints on the Phase 2a public allowlist (`GET /api/v1/public/stores/{slug}/metaobjects`)
- Reference support in metafield definitions (`type=reference`)

**Out of scope:**

- Storefront rendering of metaobjects (headless contract only) — owned by ADR-0015 storefront contract
- Bulk import of records — owned by [T-2A13-02 importer set](./T-2A13-02 importer set.md)

## Acceptance criteria

1. **AC-T-2A05-02-1** — Record fields validate against the definition's `field_defs`: unknown fields, type mismatches, and missing required fields each reject with named validation codes; handles are unique per tenant.
2. **AC-T-2A05-02-2** — Public surface serves published records only: unpublished records return 404 on the public endpoint while remaining visible under the admin surface (fail-closed publication gate).
3. **AC-T-2A05-02-3** — Public metaobject reads are on the CI-pinned public allowlist; the allowlist test fails for any undeclared public route (EXP-006 pinning).
4. **AC-T-2A05-02-4** — Events `content.metaobject.published` / `.unpublished` are emitted with definition + record references.
5. **AC-T-2A05-02-5** — GIVEN a principal lacking `content:metaobject:view` / `content:metaobject:create` / `content:metaobject:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A05-02-6** — Tenant isolation holds: every new table (`metaobject_definitions`, `metaobject_records`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A05-02-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
