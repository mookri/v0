## Objective

Line-level purchase constraints — minimum/maximum quantity per order and increment steps — are declared per product/variant and enforced in the cart mutation path and the checkout pipeline. Most specific rule wins (variant > product > store default), and buy rules never override stock truth.

## Scope

**In scope:**

- `checkout_buy_rules` entity (store_id NULL = all stores, variant_id NULL = product-level, min_qty/max_qty/increment, status)
- Resolution with specificity precedence; enforcement at cart add/update and in the checkout pipeline
- Rule configuration endpoints under the checkout extensions surface
- Stable rejection envelope codes for each violation class (min, max, increment)

**Out of scope:**

- Stock availability enforcement (inventory truth always wins) — owned by Phase 1 inventory baseline
- Per-customer quantity limits — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-2A03-01-1** — Rule specificity holds: GIVEN a variant-level and a product-level rule for the same variant WHEN a cart line is evaluated THEN the variant-level rule applies; removing it falls back to product-level, then store default.
2. **AC-T-2A03-01-2** — GIVEN a rule with min_qty 5 and increment 5 WHEN a cart add of qty 3 is requested THEN the request is rejected with a named envelope code identifying the min/increment violation; qty 10 passes.
3. **AC-T-2A03-01-3** — Buy rules never override stock truth: GIVEN a buy rule permitting qty 100 and available stock 2 WHEN checkout validates THEN the stock guard rejects first (inventory precedence asserted in the feature suite).
4. **AC-T-2A03-01-4** — Cart mutation and checkout responses carry stable machine-readable codes for buy-rule violations (`buy_rule_min_qty`, `buy_rule_max_qty`, `buy_rule_increment`) — asserted by contract tests.
5. **AC-T-2A03-01-5** — GIVEN a principal lacking `checkout:buy_rule:view` / `checkout:buy_rule:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A03-01-6** — Tenant isolation holds: every new table (`checkout_buy_rules`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A03-01-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
