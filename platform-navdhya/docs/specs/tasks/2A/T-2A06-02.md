## Objective

POS terminals carry peripheral configuration: `pos_terminal_peripherals` rows per terminal (receipt printer, barcode scanner, cash drawer, customer display) with driver selection and config JSON. Peripherals are configuration only — printing/scanning executes locally on the terminal; the platform never spools print jobs in v1. Pairing remains the sensitive step.

## Scope

**In scope:**

- `pos_terminal_peripherals` entity (terminal_id, kind, name, driver, config JSON, status)
- Peripheral CRUD under `pos:terminal:configure` (added to the pos permission set)
- Config validation per driver kind; terminal-scoped reads

**Out of scope:**

- Print-job spooling/server-side rendering of receipts — owned by Explicitly out of v1
- Peripheral health monitoring — owned by Deferred

## Acceptance criteria

1. **AC-T-2A06-02-1** — Peripheral rows are unique per (terminal, kind, name); config JSON validates against the declared driver's schema, and invalid driver/kind combinations reject with a named code.
2. **AC-T-2A06-02-2** — Peripheral configuration never triggers platform-side spooling: no print-job table or queue exists after this task (absence asserted in the architecture test).
3. **AC-T-2A06-02-3** — Event `pos.terminal.peripheral_updated` is emitted with terminal + peripheral identifiers; terminal pairing (`pos:terminal:pair`, sensitive) remains the only sensitive POS terminal operation.
4. **AC-T-2A06-02-4** — GIVEN a principal lacking `pos:terminal:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
5. **AC-T-2A06-02-5** — Tenant isolation holds: every new table (`pos_terminal_peripherals`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
6. **AC-T-2A06-02-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
