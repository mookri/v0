## Objective

In-person fulfillment lands as additive shipping method kinds: `pickup_locations` (doubling as public store-locator entries) bind to store warehouses, `ShippingQuote` offers pickup options when the cart's variants are available at the bound location, choosing pickup suppresses the shipping-address requirement and sets fulfillment intent `pickup_at`, and the BOPIS lifecycle runs confirm → pick → ready-for-pickup notification → POS completion through the same event path as regular POS sales.

## Scope

**In scope:**

- `pickup_locations` entity (address JSON, lat/lng, hours, instructions, status); `shipping_methods.kind` gains `local_pickup`
- Checkout integration: availability per location via `StockAvailability`; contact-details requirement retained
- BOPIS fulfillment flow + `POST /api/v1/pos/pickups/{orderId}:complete` (`pos:terminal:operate`)
- Public store locator endpoint on the CI-pinned public allowlist

**Out of scope:**

- Local delivery (zones, fees, cutoffs) — owned by [T-2A09-02](./T-2A09-02.md)
- Route batching for deliveries — owned by Post-v1

## Acceptance criteria

1. **AC-T-2A09-01-1** — `ShippingQuote` returns pickup options only when the cart's variants are available at a pickup location's bound warehouse (per-location `StockAvailability`); unavailable locations are absent from the quote, never shown as unavailable.
2. **AC-T-2A09-01-2** — Choosing `local_pickup` suppresses the shipping-address requirement (contact details still required) and sets the order's fulfillment intent `pickup_at = location_id`.
3. **AC-T-2A09-01-3** — BOPIS lifecycle holds: confirmed order → store pick (inventory issue) → `ready_for_pickup` notification → `POST /api/v1/pos/pickups/{orderId}:complete` marks the order fulfilled through the same event path as standard POS sales.
4. **AC-T-2A09-01-4** — Public endpoint `GET /api/v1/public/stores/{slug}/locations` returns active pickup locations (name, address, hours) and is on the CI-pinned public allowlist; undeclared public routes fail the allowlist build.
5. **AC-T-2A09-01-5** — Pickup completion emits the standard POS fulfillment events with the order + location references (no parallel event namespace).
6. **AC-T-2A09-01-6** — GIVEN a principal lacking `shipping:pickup_location:view` / `shipping:pickup_location:create` / `pos:terminal:operate` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-2A09-01-7** — Tenant isolation holds: every new table (`pickup_locations`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-2A09-01-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
