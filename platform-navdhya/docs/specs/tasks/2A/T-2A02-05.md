## Objective

Placed orders receive asynchronous post-capture risk annotation: deterministic v1 rules (velocity, amount threshold, address/billing mismatch, first-time high value) score the order, write `order_risk_assessments`, mirror the verdict onto the order, notify staff on high risk, and feed anomaly detection as a candidate signal. Risk annotation never blocks or reverses a capture that already happened.

## Scope

**In scope:**

- Async listener consuming `checkout.order.placed`
- Deterministic rule set with per-rule signal attribution
- `order_risk_assessments` + `sales_orders.risk_verdict` mirror
- Staff notification on high verdict; candidate signal emission for intelligence layer

**Out of scope:**

- Pre-capture fraud blocking (post-v1 policy layer, per ADR-0013)
- ML scoring models (intelligence phase) — owned by P6 roadmap

## Acceptance criteria

1. **AC-T-2A02-05-1** — GIVEN a placed order WHEN the risk listener runs THEN an assessment row is written with per-rule signals and the verdict mirrors to `sales_orders.risk_verdict`; the listener consumes `checkout.order.placed` asynchronously and never participates in the capture transaction (ADR-0013).
2. **AC-T-2A02-05-2** — High-risk verdicts notify staff through the notifications service and emit the anomaly candidate signal; low/medium verdicts produce no notifications.
3. **AC-T-2A02-05-3** — Event `order_ops.risk.assessed` is emitted with order reference + verdict (signals summary, no full PII).
4. **AC-T-2A02-05-4** — Rule evaluation is deterministic: identical order fixtures yield identical verdicts across runs (no time-of-day or external-state dependence except declared rule inputs).
5. **AC-T-2A02-05-5** — GIVEN a principal lacking `order_ops:risk:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A02-05-6** — Tenant isolation holds: every new table (`order_risk_assessments`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A02-05-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
