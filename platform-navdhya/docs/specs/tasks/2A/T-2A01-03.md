## Objective

Markets sell with landed-cost presentation: per-market duty schedules (HSN/SAC rates, ad-valorem or specific) are applied at checkout per the market's `duty_mode` (`at_checkout` charges now, `deferred` estimates only, `none` skips), and the market's `tax_display` (`inclusive|exclusive`) drives storefront/checkout price presentation with the rounding rule applied consistently.

## Scope

**In scope:**

- `market_duty_rates` configuration surface (per market, per catalog tax code)
- Checkout pipeline duty step: compute duty lines via the tax engine's additive-component mechanism
- `tax_display` enforcement in storefront/checkout price rendering + rounding rule application
- Duty estimate presentation for `deferred` mode (clearly labeled, never captured)

**Out of scope:**

- Statutory customs filing (duty here is a commercial charge, not a filing) — owned by India statutory package (E-4A-08)
- Carrier/third-party duty collection integrations — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-2A01-03-1** — GIVEN a market with `duty_mode=at_checkout` and a matching HSN duty rate WHEN checkout computes totals THEN a duty line is added via the tax engine's additive-component mechanism with the correct method (ad-valorem % or specific amount) and appears in the order totals.
2. **AC-T-2A01-03-2** — GIVEN `duty_mode=deferred` WHEN checkout completes THEN no duty amount is captured; the response carries a labeled duty estimate only, and the order's payment totals exclude duty.
3. **AC-T-2A01-03-3** — Tax display holds: `inclusive` markets render storefront and checkout prices with tax included, `exclusive` markets render net with a computed tax line; the market's rounding rule is applied at the same stage in both modes (no rounding drift between display and capture).
4. **AC-T-2A01-03-4** — Event `markets.duty_rate.updated` is emitted on duty schedule changes with market + rate identifiers (no commercial amounts required in payload).
5. **AC-T-2A01-03-5** — GIVEN a principal lacking `markets:duty:view` / `markets:duty:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A01-03-6** — Tenant isolation holds: every new table (`market_duty_rates`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A01-03-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
