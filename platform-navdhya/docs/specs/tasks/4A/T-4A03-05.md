## Objective

PO `kind` gains `subcontract` (additive): PO lines name the finished variants while `subcontract_components` lines name components to be supplied. Component issue moves tenant stock to a virtual `supplier_floor` location kind (components remain valued tenant stock); the GRN receives finished goods normally and consumes components per BOM ratio via the manufacturing `BomLookup` contract, with variances posted as `subcontract_variance` adjustments. A subcontract PO may reference a work order (`work_order_ref`), and work-order close reconciles issued vs consumed components.

## Scope

**In scope:**

- PO `kind` gains `subcontract` (additive); `subcontract_components` lines name the components to be supplied against the finished variants on PO lines
- Component issue: `POST /purchase-orders/{id}:issue-components` creates inventory movements (`subcontract_issue`) from stock to a `supplier_floor` location kind (inventory location kinds gain `supplier_floor`); components remain tenant stock (valued)
- Receipt: GRN against the subcontract PO receives finished goods (normal receipt movements) and consumes components per BOM ratio (manufacturing `BomLookup` contract); variances post as adjustments with reason `subcontract_variance`
- Work-order linkage: `work_order_ref` on the PO; work-order close reconciles issued vs consumed components
- Events `purchasing.subcontract.components_issued` / `.received`

**Out of scope:**

- Supplier-managed consignment stock valuation models — owned by Deferred post-v1
- Multi-level BOM subcontracting (one level of components in v1) — owned by By design

## Acceptance criteria

1. **AC-T-4A03-05-1** — Component issue correctness: `POST /purchase-orders/{id}:issue-components` creates `subcontract_issue` movements from stock to a `supplier_floor` location; stock levels at the source location decrease, the `supplier_floor` location holds the issued qty, and the components remain valued tenant stock (valuation unchanged, location moved).
2. **AC-T-4A03-05-2** — Receipt consumption: GIVEN a subcontract PO whose finished variant has a BOM of 2× component A WHEN a GRN receives 10 finished units THEN 20 units of component A are consumed from `supplier_floor` per the `BomLookup` ratio; issued-but-unconsumed components remain at the supplier floor as tenant stock.
3. **AC-T-4A03-05-3** — Variance handling: WHEN actual consumption differs from BOM ratio (damaged/extra components) THEN the difference posts as an inventory adjustment with reason `subcontract_variance`, and work-order close (where `work_order_ref` is set) reconciles issued vs consumed with the residual surfaced in the reconciliation report.
4. **AC-T-4A03-05-4** — The PO core state machine is untouched: subcontract POs flow through the same draft → approved → received states as standard POs — no subcontract-specific transitions exist (asserted by state-machine test + architecture test).
5. **AC-T-4A03-05-5** — Events `purchasing.subcontract.components_issued` (movement refs) and `purchasing.subcontract.received` (GRN ref, finished + consumed line refs) are emitted; component issue runs under `purchasing:order:update` and receipt under the existing `purchasing:receipt:create` (no new permissions).
6. **AC-T-4A03-05-6** — GIVEN a principal lacking `purchasing:order:update` / `purchasing:receipt:create` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A03-05-7** — Tenant isolation holds: every new table (`subcontract_components`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A03-05-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
