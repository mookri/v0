## Objective

Operators report work-order operations: `manufacturing_operation_reports` capture per-step completion (qty_completed, qty_rejected, labor/machine time, downtime) against routing steps that gain additive `quality_gate` (bool) and `report_mode` (`quantity|time|both`) columns. A step's completion report is accepted only when the preceding step's quality gate (if any) has a passed inspection — otherwise 422 `manufacturing_gate_not_cleared` (gate state consumed from quality, T-4A06-01). Reports advance work-order progress per step; labor + machine time accumulate on the work order and are absorbed into output cost at close (additive cost components). Rejected qty at a quality-gated step auto-creates an NCR with source `in_process` (exactly one per rejection report). The report endpoint is idempotent per (step, started_at).

## Scope

**In scope:**

- `manufacturing_operation_reports` (work_order_id, step_id routing step, work_center_id, reported_by membership_id, qty_completed, qty_rejected, started_at, completed_at NULL, downtime_minutes, notes)
- Routing steps gain additive `quality_gate` (bool) + `report_mode` (`quantity|time|both`) columns
- Gate check: a step's completion report is accepted only when the **preceding** step's quality gate (if any) has a passed inspection (quality gate-state query, T-4A06-01); otherwise 422 `manufacturing_gate_not_cleared`
- Reports advance work-order progress (completed qty per step); labor + machine time accumulate on the work order and are absorbed into output cost at close (additive cost components)
- Rejected qty at a quality-gated step auto-creates an NCR with source `in_process` (T-4A06-02 machinery; exactly one NCR per rejection report, idempotent on report ref)
- `POST /work-orders/{id}/operations/{stepId}:report` (`manufacturing:operation:report`, idempotent per (step, started_at)); `GET /work-orders/{id}/operation-reports` (`manufacturing:operation:view`)
- Events `manufacturing.operation.reported`, `manufacturing.operation.completed`

- Operator terminal UI choreography — owned by Experience phase

## Acceptance criteria

1. **AC-T-4A10-01-1** — Gate enforcement holds: GIVEN a routing where step 2 follows a step flagged `quality_gate=true` without a passed inspection WHEN step 2's completion report is submitted THEN the request rejects with 422 `manufacturing_gate_not_cleared`; after the gate's inspection passes (T-4A06-01), the identical report succeeds.
2. **AC-T-4A10-01-2** — `POST /work-orders/{id}/operations/{stepId}:report` is idempotent per (step, started_at): replaying the same report returns the stored result without double-counting completed qty or time; reports validate against the routing (unknown step ids reject) and `report_mode` (`quantity|time|both` governs which fields are required).
3. **AC-T-4A10-01-3** — Progress + time accumulation: reports increment the work order's completed qty per step and accumulate labor + machine time; at work-order close the accumulated time is absorbed into output cost as additive cost components — close posting remains balanced (fixture-asserted amounts).
4. **AC-T-4A10-01-4** — NCR auto-creation: GIVEN rejected qty > 0 at a quality-gated step WHEN the report is accepted THEN exactly one NCR is created with source `in_process` + subject ref to the work order/step (T-4A06-02 machinery); a replayed report creates no second NCR (idempotent on report ref).
5. **AC-T-4A10-01-5** — Events `manufacturing.operation.reported` (work order, step, qty summary) and `manufacturing.operation.completed` (step completion) are emitted; payloads carry refs + quantities, never cost amounts (costs stay on the ledger).
6. **AC-T-4A10-01-6** — GIVEN a principal lacking `manufacturing:operation:report` / `manufacturing:operation:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A10-01-7** — Tenant isolation holds: every new table (`manufacturing_operation_reports`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A10-01-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
