## Objective

The invoicing numbering-scheme pattern is generalized into a kernel-adjacent registry consumed by **all** numbered document types: `document_numbering_schemes` (doc_type UQ per tenant across the platform's document-type enum — quote, sales_order, draft_order, purchase_order, requisition, grn, invoice, credit_note, bill, debit_note, journal_entry, transfer, adjustment, rma, work_order, expense_report, contract, ncr, capa — plus prefix, sequence_scope `tenant|fiscal_year|calendar_year`, padding, current_value, gapless default true, effective_from, status). Allocation goes through one contract: `NumberAllocator.next(doc_type, context)` — atomic row-locked increment; gapless schemes MUST NOT skip values (failed allocations roll back with the enclosing transaction); non-gapless schemes audit skipped ranges. Scheme changes are effective-dated and audited; issued numbers are never renumbered. Existing per-module sequences backfill into the registry with observable numbering behavior unchanged (regression-tested).

## Scope

**In scope:**

- `document_numbering_schemes`: `doc_type` (UQ per tenant; the full document-type enum), `prefix`, `sequence_scope` (`tenant|fiscal_year|calendar_year`), `padding`, `current_value`, `gapless` (bool, default true), `effective_from`, `status`
- Allocation contract `NumberAllocator.next(doc_type, context)`: atomic row-locked increment; gapless schemes MUST NOT skip values (failed allocations roll back with the enclosing transaction); non-gapless schemes audit skipped ranges
- Scheme changes are effective-dated and audited; numbers already issued are never renumbered
- Migration: existing per-module sequences backfill into the registry; observable numbering behavior is unchanged (regression-tested per migrated module)
- Events `platform.numbering.scheme_updated`. Permission: `platform:numbering:configure` (sensitive; platform namespace)

**Out of scope:**

- Renumbering of already-issued numbers — prohibited by design — owned by By design
- Document-format templates beyond prefix/padding/scope (layout is a document concern) — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A12-02-1** — Concurrent allocation: GIVEN a gapless scheme WHEN racing `NumberAllocator.next` calls execute THEN every caller receives a unique number and the sequence is gapless (concurrency test); a failed allocation rolls back with its enclosing transaction leaving no gap in the sequence.
2. **AC-T-4A12-02-2** — Gapless vs non-gapless semantics: gapless schemes never skip (asserted across fault-injected failures); non-gapless schemes may skip but every skipped range is audited (audit-record fixture test).
3. **AC-T-4A12-02-3** — Scheme-change invariants: scheme edits are effective-dated and audited — numbers already issued are never renumbered (immutable), and numbers issued after `effective_from` follow the new scheme; mid-transaction scheme changes never split a single allocation (feature matrix).
4. **AC-T-4A12-02-4** — Backfill regression: existing per-module sequences (orders, invoices, POs, journals, and the remaining document types) backfill into the registry and produce byte-identical numbering for the same fixture operations — regression fixtures per migrated module assert observable behavior is unchanged.
5. **AC-T-4A12-02-5** — Event `platform.numbering.scheme_updated` is emitted on scheme changes with the scheme ref + effective date; configuration requires `platform:numbering:configure` with step-up (sensitive, platform namespace) and writes an audit record naming the actor.
6. **AC-T-4A12-02-6** — GIVEN a principal lacking `platform:numbering:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A12-02-7** — Tenant isolation holds: every new table (`document_numbering_schemes`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A12-02-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).

## Risks & notes

- Backfill runs against live per-module sequences — the migration is idempotent and re-runnable, with numbering regression fixtures gating each module's cutover
