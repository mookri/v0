## Objective

Profitability is an analytics read model built purely from posted journal lines (gl events): revenue accounts vs COGS vs directly-attributed expense lines, sliced by dimension (org / cost center / project / customer via dimension refs). Project profitability (ERP-135) uses the project dimension populated by project billing postings; customer profitability uses the customer ref on AR revenue lines. Margin thresholds per view (tenant config) emit `finance_reports.margin.below_threshold` (debounced per period + slice) feeding anomaly detection. The module publishes `ProfitabilityQuery` (analytics-owned) consumed by dashboards and copilot tooling within effective authority — existing `finance_reports:report:view` permission, no new permissions.

## Scope

**In scope:**

- Profitability read model in analytics built from posted journal lines (gl events): revenue vs COGS vs directly-attributed expense lines, sliced by dimension (org / cost center / project / customer via `dimension` refs) — event-built, no cross-module joins (ADR-0011)
- Project profitability (ERP-135) via the project dimension populated by project billing postings; customer profitability via the customer ref on AR revenue lines
- Margin thresholds per view (tenant config) → `finance_reports.margin.below_threshold` (debounced per period + slice) feeding anomaly detection (intelligence consumes)
- `ProfitabilityQuery` contract published (analytics-owned; consumed by dashboards + copilot tooling within effective authority)

**Out of scope:**

- Contribution-margin allocation rules beyond direct attribution (overhead allocation is a finance project) — owned by Deferred post-v1
- Forecast profitability (intelligence consumes the read model + events) — owned by P6 roadmap

## Acceptance criteria

1. **AC-T-4A11-02-1** — Event-built correctness: a fixture stream of posted journal lines (revenue, COGS, attributed expenses across org/cost-center/project/customer dimensions) converges to the expected profitability slices — reconciliation test asserts read model = hand-computed margins per slice; listeners consume gl events only (architecture test asserts no cross-module joins or direct ledger reads).
2. **AC-T-4A11-02-2** — Project + customer profitability: project slices use the project dimension populated by project billing postings (ERP-135), customer slices use the customer ref on AR revenue lines — fixture assertions cover both; slices with missing dimension refs land in an unattributed bucket (never dropped).
3. **AC-T-4A11-02-3** — Margin threshold events: GIVEN a tenant threshold of 20% on the cost-center view WHEN a period slice computes 15% margin THEN `finance_reports.margin.below_threshold` emits once (debounced per period + slice — recomputation within the same period/slice does not re-emit); recovery above threshold emits no event.
4. **AC-T-4A11-02-4** — `ProfitabilityQuery` serves dashboards + copilot tooling within effective authority: a principal's visible slices are restricted to their org/dimension visibility (authorization matrix test); the existing `finance_reports:report:view` permission guards all reads (no new permissions introduced).
5. **AC-T-4A11-02-5** — Read-model refresh is idempotent: replaying the same gl event batch yields identical slices (refreshed_at advances once); `finance_reports.margin.below_threshold` carries period + slice keys + computed margin, never ledger amounts.
6. **AC-T-4A11-02-6** — GIVEN a principal lacking `finance_reports:report:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A11-02-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
