## Objective

The contracts module lands with its full lifecycle: `contracts` (number `CTR-<yyyy>-<seq>`, customer_id, kind `sales_contract|service_contract|warranty`, status machine `draft|active|expired|terminated|renewed`, starts_on/ends_on, auto_renew, renewal_term JSON, currency, totals JSON, no soft delete — audit trail instead) + `contract_lines` (variant/description, qty, unit_price, coverage JSON) + `contract_renewals` (one pending renewal per contract, UQ). Activation guards (signed, ≥1 line, starts_on ≤ ends_on) precede a scheduler-driven renewal orchestration: contracts with `ends_on` inside the tenant's renewal window (default 60 days) get a `pending` renewal, an optional auto-quote via the sales `QuoteDraftFactory` contract (status `quoted`), and an idempotent `:convert` that extends the contract per `renewal_term` (emitting `contracts.contract.renewed`). Unconverted contracts lapse (`expired` + renewal `lapsed`). Termination is sensitive (ACR 2, mandatory reason) with remaining-value credit notes via the invoicing contract.

## Scope

**In scope:**

- `contracts` (number `CTR-<yyyy>-<seq>`, customer_id, kind `sales_contract|service_contract|warranty`, status machine `draft|active|expired|terminated|renewed`, starts_on, ends_on, auto_renew, renewal_term JSON {months, price_rule}, currency, totals JSON; soft delete prohibited — audit) + `contract_lines` (variant_id NULL, description, qty, unit_price Money, coverage JSON NULL) + `contract_renewals` (renewal_number, due_at, status `pending|quoted|converted|lapsed`, quote_id NULL, converted_at NULL; UQ one pending renewal per contract)
- Activation: `draft → active` when staff marks signed (audited); guards — `starts_on ≤ ends_on`, ≥1 line
- Renewal orchestration: kernel lock-based scheduler scans contracts with `ends_on` within the tenant's renewal window (default 60 days) and no pending renewal → creates `contract_renewals` (`pending`) → optional auto-quote via sales `QuoteDraftFactory` → status `quoted`
- `:convert` (`contracts:renewal:convert`, idempotent): extends the contract (`ends_on` += renewal_term months, `renewal_number` + 1, price per `price_rule`), emits `contracts.contract.renewed`
- Lapse path: `ends_on` passed without conversion → contract `expired`, renewal `lapsed`, emits `contracts.renewal.lapsed`
- Termination: `:terminate` (`contracts:contract:terminate`, sensitive, ACR 2, mandatory reason) → `terminated`; remaining-value credit note via the invoicing contract
- Events `contracts.contract.created` / `.activated` / `.expired` / `.terminated` / `.renewed`, `contracts.renewal.due` / `.quoted` / `.converted` / `.lapsed`

**Out of scope:**

- Warranty coverage mechanics (kind=warranty records share this task's tables; coverage contract is separate) — owned by [T-4A09-02](./T-4A09-02.md)
- Revenue recognition schedules (finance consumes activation/renewal events) — owned by Finance baseline
- Contract negotiation / redlining workflows — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A09-01-1** — Activation guards hold: GIVEN a draft contract with 0 lines WHEN `:activate` is called THEN activation rejects with a named error; GIVEN ≥1 line and starts_on > ends_on THEN activation rejects; a valid contract activates with an audit record of the signing mark.
2. **AC-T-4A09-01-2** — Renewal orchestration safety: the scheduler creates exactly one pending renewal per contract inside the renewal window — a double scheduler run (lock contention/retry) never creates a second pending renewal (unique constraint asserted); `contracts.renewal.due` emits once per renewal; auto-quoting via `QuoteDraftFactory` transitions the renewal to `quoted` carrying the quote id.
3. **AC-T-4A09-01-3** — `POST /api/v1/contracts/renewals/{id}:convert` is idempotent: the first call extends `ends_on` by `renewal_term` months at the `price_rule` price, increments `renewal_number`, and emits `contracts.contract.renewed`; replaying returns the stored result without double-extension; converting a lapsed/expired renewal rejects.
4. **AC-T-4A09-01-4** — Lapse + termination paths: GIVEN a contract past `ends_on` with an unconverted renewal WHEN the lapse job runs THEN the contract is `expired` and the renewal `lapsed` with `contracts.renewal.lapsed` emitted; `:terminate` requires ACR 2 step-up + a mandatory reason (missing reason rejects), sets `terminated`, writes the audit record, and hands the remaining-value credit note to invoicing via its published contract.
5. **AC-T-4A09-01-5** — Soft delete is prohibited on `contracts` (audit trail requirement — model + migration test); `contract_renewals` enforces UQ one pending renewal per contract; totals JSON recomputes on line changes within the same transaction.
6. **AC-T-4A09-01-6** — Events `contracts.contract.created` / `.activated` / `.expired` / `.terminated` / `.renewed` and `contracts.renewal.due` / `.quoted` / `.converted` / `.lapsed` are emitted with contract/renewal refs; `.terminated` carries the mandatory reason; payloads carry no PII beyond membership/customer ids.
7. **AC-T-4A09-01-7** — GIVEN a principal lacking `contracts:contract:view` / `contracts:contract:create` / `contracts:contract:update` / `contracts:contract:terminate` / `contracts:renewal:view` / `contracts:renewal:convert` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
8. **AC-T-4A09-01-8** — Tenant isolation holds: every new table (`contracts`, `contract_lines`, `contract_renewals`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
9. **AC-T-4A09-01-9** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
