## Objective

Supplier performance moves from snapshot rows to a computed scoring system: a monthly job per supplier computes on-time % (GRN date vs PO promised date), price variance (PO unit cost vs prior cost trend), quality rejection % (GRN rejected qty / received qty, including quality NCR references when enabled), and RFQ responsiveness; a weighted composite yields a grade (`a|b|c|d`) stored as the period's `supplier_performance` row. Grades feed `SupplierLookup` (additive fields) and replenishment preference, and the computed event carries grade only — no commercial amounts.

## Scope

**In scope:**

- Monthly scoring job per supplier: on-time %, price variance, quality rejection %, RFQ responsiveness (all from purchasing/GRN history local to suppliers' read surface)
- Weighted composite → grade (`a|b|c|d`) stored as the period's `supplier_performance` row (extends the existing table from snapshots to computed scoring)
- Grade feeds `SupplierLookup` (additive fields) + replenishment preference (supply-chain consumes)
- Event `suppliers.scorecard.computed` (supplier_id, period, grade — no commercial amounts in payload)

**Out of scope:**

- Supplier portal self-service review of scores — owned by Deferred post-v1
- Score appeal / correction workflows beyond manual re-run — owned by By design

## Acceptance criteria

1. **AC-T-4A03-04-1** — Metric correctness: GIVEN fixture GRN/PO/RFQ history WHEN the monthly job runs THEN on-time % = on-time GRNs / total GRNs by promised date, price variance follows the PO unit-cost trend rule, rejection % = rejected qty / received qty, and RFQ responsiveness = reply rate — each asserted against hand-computed fixtures.
2. **AC-T-4A03-04-2** — Composite + grade: the weighted composite maps to grades `a|b|c|d` at the tenant's configured thresholds; the period's `supplier_performance` row stores component metrics + composite + grade, and a re-run for the same (supplier, period) upserts idempotently (no duplicate rows).
3. **AC-T-4A03-04-3** — `SupplierLookup` exposes grade + period as additive fields, and replenishment preference ordering consumes them (feature test asserts preferred-grade suppliers sort first where configured).
4. **AC-T-4A03-04-4** — Event `suppliers.scorecard.computed` carries supplier_id, period, and grade only — a payload-schema test asserts no monetary amounts or commercial fields appear in the event.
5. **AC-T-4A03-04-5** — Quality rejection % includes NCR references when the quality module is enabled and degrades gracefully to GRN rejected-qty-only when it is not (both modes feature-tested).
6. **AC-T-4A03-04-6** — GIVEN a principal lacking `suppliers:scorecard:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A03-04-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
