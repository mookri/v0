## Objective

E-way bill registration as a second adapter in the India statutory package: triggered by `shipping.shipment.shipped` for inter-state movement above the statutory value threshold (tenant config), or generated manually for pre-transport. The adapter composes the e-way bill (parties, goods, HSN, value, distance from address geo, transport details) and registers it with the configured portal endpoint; `eway_bill_number` + `eway_valid_to` are stored on the shipment (additive). An expiry job warns before validity lapse (`india_statutory.eway.expiring`); extension is handled by re-generation (new number). Same adapter rules as the package: configuration-only endpoints, idempotency keys (shipment ref), sandbox mode, pinned schema versions.

## Scope

**In scope:**

- Trigger listener on `shipping.shipment.shipped` for inter-state movement above the statutory value threshold (tenant config); manual generation endpoint for pre-transport bills
- E-way bill composition: parties, goods, HSN, value, distance from address geo, transport details; schema version pinned per adapter release
- Registration via the configured e-way portal endpoint (channel adapter: retries + circuit breaker + idempotency key = shipment ref); `eway_bill_number` + `eway_valid_to` stored on the shipment (additive)
- Expiry job: warns before validity lapse (`india_statutory.eway.expiring`); extension = re-generation yielding a new bill number
- Events `india_statutory.eway.generated` / `.expiring` / `.expired`

**Out of scope:**

- IRN registration (separate adapter) — owned by [T-4A08-01](./T-4A08-01.md)
- Transporter self-service portal — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A08-02-1** — Threshold + geography gating: GIVEN an intra-state shipment WHEN shipped THEN no e-way bill is generated; GIVEN an inter-state shipment above the statutory value threshold WHEN shipped THEN the adapter registers a bill and stores `eway_bill_number` + `eway_valid_to`; below threshold no bill is generated unless manually requested (feature matrix).
2. **AC-T-4A08-02-2** — Idempotent registration: adapter calls carry the shipment-ref idempotency key — a retried registration for the same shipment never produces a second bill number (mock-provider test); sandbox mode returns deterministic mock numbers.
3. **AC-T-4A08-02-3** — Expiry lifecycle: the expiry job emits `india_statutory.eway.expiring` before `eway_valid_to` lapses and `india_statutory.eway.expired` after; requesting an extension generates a NEW bill number (re-generation path) rather than mutating the expired one.
4. **AC-T-4A08-02-4** — Payload correctness: the composed bill matches the pinned schema fixture — parties, goods with HSN, declared value, distance computed from address geo, transport details; emitted schema version recorded on the artifact.
5. **AC-T-4A08-02-5** — Events `india_statutory.eway.generated` (shipment ref + bill number + valid_to), `.expiring`, `.expired` are emitted; payloads carry refs + validity, never tax amounts.
6. **AC-T-4A08-02-6** — GIVEN a principal lacking `india_statutory:eway:view` / `india_statutory:eway:create` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A08-02-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
