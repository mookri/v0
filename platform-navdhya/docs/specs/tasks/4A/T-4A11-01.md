## Objective

Journal lines become dimension-aware: `finance_cost_centers` (code UQ per tenant, name, org_id NULL default binding, status) + `finance_dimension_rules` (account selector by code range/type, `required_dimensions` JSON — `cost_center`, `project`, custom keys, status). The posting engine validates every line against the rules; a required dimension missing or invalid rejects the ENTIRE entry into `posting_errors` with reason `dimension_missing` — never posted partially. Manual journals expose dimension entry with console-side validation before submit, and finance_reports gains the `cost_center_trial_balance` definition (trial balance sliced by cost-center dimension, same queued org-scoped mechanics).

## Scope

**In scope:**

- `finance_cost_centers` (code UQ per tenant, name, org_id NULL — default org binding, status) + `finance_dimension_rules` (account selector: code range/type, `required_dimensions` JSON (`cost_center`, `project`, custom keys), status)
- Posting validation: the posting engine validates every journal line against `finance_dimension_rules`; a required dimension missing/invalid ⇒ the entry is rejected into `posting_errors` with reason `dimension_missing` — never posted partially
- Manual journals expose dimension entry; the console validates dimensions before submit (client-side guard, server remains authoritative)
- `cost_center_trial_balance` report definition in finance_reports — trial balance sliced by cost-center dimension, same mechanics (queued, org-scoped)
- Events `gl.cost_center.created` / `.updated`. Permissions: `gl:cost_center:view|configure` (configure sensitive)

**Out of scope:**

- Dimension hierarchies / rollup trees beyond flat cost centers — owned by Deferred post-v1
- Budget-vs-actual control by cost center (budgets module consumes the dimension) — owned by Budgets baseline

## Acceptance criteria

1. **AC-T-4A11-01-1** — Dimension validation holds: GIVEN a dimension rule requiring `cost_center` on expense accounts WHEN a journal line on a matched account omits the cost center THEN the entire entry is rejected into `posting_errors` with reason `dimension_missing` — no line posts partially; with a valid cost center the entry posts normally (both paths feature-tested).
2. **AC-T-4A11-01-2** — Rule matching correctness: rules select accounts by code range/type; multiple matching rules compose (union of required dimensions); a rule with status inactive is ignored — the matching matrix is fixture-tested including overlapping ranges.
3. **AC-T-4A11-01-3** — Cost-center trial balance: the `cost_center_trial_balance` definition produces a trial balance sliced by cost-center dimension using the standard queued, org-scoped report mechanics — output for a fixture period matches hand-computed balances per cost center, and org scoping restricts rows to the recipient's org visibility.
4. **AC-T-4A11-01-4** — `finance_cost_centers` codes are UQ per tenant; `required_dimensions` JSON validates against the known dimension keys (`cost_center`, `project`, registered custom keys — unknown keys reject at configure time); cost center configure is sensitive (step-up) and audited.
5. **AC-T-4A11-01-5** — Events `gl.cost_center.created` / `.updated` are emitted with cost center refs (no amounts); dimension rule changes write audit records (configuration sensitivity class).
6. **AC-T-4A11-01-6** — GIVEN a principal lacking `gl:cost_center:view` / `gl:cost_center:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A11-01-7** — Tenant isolation holds: every new table (`finance_cost_centers`, `finance_dimension_rules`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A11-01-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).

## Risks & notes

- Posting-engine hook must fail fast and cheaply — rule matching is index-backed and cached per transaction; a misconfigured rule must not deadlock posting (circuit-break at rejection, observable via `posting_errors`)
- Dimension validation applies to ALL posting sources (sub-modules post through the engine) — integration fixtures cover expenses, manufacturing scrap, and dunning fee postings with dimensions
