## Objective

Drop-shipped lines bypass stock reservation and instead auto-create supplier POs on order confirmation: lines flagged `drop_ship=true` are skipped by the inventory reservation listener; on `sales.order.confirmed` a purchasing listener creates one PO per supplier via the new additive `PurchaseOrderFactory` contract (unit cost from `supplier_items.last_cost`, ship-to = customer shipping address, `drop_ship_ref=order_line_id`). GRN against a drop-ship PO performs no stock movement; instead it emits `purchasing.receipt.dropship_completed`, which the sales listener maps to line fulfillment so inventory emits a virtual `inventory.fulfillment.completed` — keeping the sales state machine untouched by drop-ship specifics.

## Scope

**In scope:**

- `drop_ship=true` line flag excluded from stock reservation (inventory listener skips)
- Auto-PO on `sales.order.confirmed`: one PO per supplier via `PurchaseOrderFactory` (additive contract published by purchasing); unit cost from `supplier_items.last_cost`, ship-to = customer shipping address, `drop_ship_ref=order_line_id`
- Drop-ship GRN performs no stock movement; emits `purchasing.receipt.dropship_completed` (line refs)
- Sales listener maps drop-ship completion to line fulfillment → inventory emits virtual `inventory.fulfillment.completed`
- Returns on drop-shipped lines follow the normal returns flow with disposition `return_to_supplier`

**Out of scope:**

- Drop-ship supplier portals / supplier self-service — owned by Deferred post-v1
- Multi-supplier split of a single line (one line = one supplier) — owned by By design

## Acceptance criteria

1. **AC-T-4A02-04-1** — Reservation exclusion holds: GIVEN an order line with `drop_ship=true` WHEN the order is confirmed THEN the inventory reservation listener skips the line (no reservation created, no shortfall flagged), while a sibling non-drop-ship line reserves normally.
2. **AC-T-4A02-04-2** — Auto-PO correctness: on `sales.order.confirmed`, exactly one PO per distinct supplier is created via `PurchaseOrderFactory` with unit cost from `supplier_items.last_cost`, ship-to = the customer's shipping address, and `drop_ship_ref=order_line_id` for each sourced line.
3. **AC-T-4A02-04-3** — Drop-ship GRN performs no stock movement (stock levels unchanged); instead it emits `purchasing.receipt.dropship_completed`, and the sales listener maps it to line fulfillment so inventory emits a virtual `inventory.fulfillment.completed` — the sales state machine has no drop-ship-specific branches (asserted by architecture test).
4. **AC-T-4A02-04-4** — Setting `drop_ship` on an order line requires `sales:order:create` (no new permission introduced); the flag is immutable once the order is confirmed.
5. **AC-T-4A02-04-5** — Events `sales.order.dropship_initiated` (on auto-PO creation) and `purchasing.receipt.dropship_completed` (line refs) are emitted; returns on drop-shipped lines use disposition `return_to_supplier`.
6. **AC-T-4A02-04-6** — GIVEN a principal lacking `sales:order:create` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A02-04-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
