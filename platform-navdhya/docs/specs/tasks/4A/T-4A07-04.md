## Objective

Light warehouse workflows on the movement model: put-away suggestions at GRN from `variant_putaway_rules` (variant-location affinity, priority) — suggestions only in v1; operator confirms or overrides (override audited). Pick lists (`inventory.pick_lists`: ref order/transfer, status, lines with movement plan + location + serial/batch refs) generate from reservations; pick-by-scan (barcode operations §7.3) walks the list; a short pick emits `inventory.pick.short`, which feeds the backorder flow (T-4A02-02). Full WMS (directed wave picking, slotting) remains deferred.

## Scope

**In scope:**

- `variant_putaway_rules` (variant_id, location_id, priority) + put-away suggestion at GRN (suggestions only; operator confirm/override, override audited)
- `inventory.pick_lists` (id, ref order/transfer, status, lines [{movement plan, location, serial/batch refs}]) generated from reservations
- Pick-by-scan integration with barcode operations (T-2A06-01 scan surface walks the list)
- Short pick: `inventory.pick.short` event feeds the backorder allocation flow (T-4A02-02)
- Events `inventory.putaway.suggested`, `inventory.pick.completed`, `inventory.pick.short`. Permissions: `inventory:pick:view|operate`, `inventory:putaway:configure`

**Out of scope:**

- Directed wave picking, slotting optimization, labor management — owned by Deferred post-v1 (full WMS)
- Pick-list UI choreography beyond scan flow — owned by Experience phase

## Acceptance criteria

1. **AC-T-4A07-04-1** — Put-away suggestions: GIVEN `variant_putaway_rules` mapping variant V → locations [L1 (priority 1), L2 (priority 2)] WHEN a GRN for V posts THEN the suggestion lists L1 first; operator confirm moves stock to the chosen location; an override to L3 succeeds with an audit record naming rule + chosen location.
2. **AC-T-4A07-04-2** — Pick-list generation: GIVEN a reservation covering 2 order lines WHEN the pick list generates THEN lines carry the movement plan, source location, and serial/batch refs from the reservation (serial-tracked lines name reserved serials); the list status machine tracks `pending → in_progress → completed`.
3. **AC-T-4A07-04-3** — Short-pick flow: WHEN a pick line reports picked qty < planned qty THEN the pick list records the short, emits `inventory.pick.short` (line + shortfall refs), and the backorder listener flags the shortfall for the next allocation run (T-4A02-02) — the pick itself completes for the picked qty.
4. **AC-T-4A07-04-4** — Pick-by-scan: scanning a location/variant barcode advances the list per the barcode operations contract (T-2A06-01); scanning a location not on the list rejects with a named error (no silent substitution).
5. **AC-T-4A07-04-5** — Events `inventory.putaway.suggested` (suggestion refs — not a blocking hook), `inventory.pick.completed` (list + movement refs), and `inventory.pick.short` (shortfall refs) are emitted; put-away suggestion emission never blocks GRN posting (async listener test).
6. **AC-T-4A07-04-6** — GIVEN a principal lacking `inventory:pick:view` / `inventory:pick:operate` / `inventory:putaway:configure` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A07-04-7** — Tenant isolation holds: every new table (`variant_putaway_rules`, `inventory.pick_lists`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A07-04-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
