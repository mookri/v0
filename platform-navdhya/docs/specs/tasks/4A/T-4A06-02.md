## Objective

Non-conformance and corrective-action management: `quality_ncrs` (sourced from inbound/in-process/outbound/customer flows incl. auto-creation from shop-floor rejected qty) carry defect code + severity and run a state machine (`open|under_review|disposed|closed`) with dispositions (`return_to_supplier|scrap|rework|use_as_is|accept_with_concession`) that drive inventory movements. `quality_capas` track corrective/preventive actions with owner + due date and a `verified` state that MUST be performed by a different membership than the owner (SoD). NCRs with severity `major|critical` require at least one verified CAPA before closure. Defect codes are seeded + tenant-defined. Rejection % feeds supplier scorecards (T-4A03-04).

## Scope

**In scope:**

- `quality_ncrs` (number `NCR-<seq>`, inspection_id NULL, source `inbound|in_process|outbound|customer`, subject ref, defect_code, severity `minor|major|critical`, status machine `open|under_review|disposed|closed`, disposition `return_to_supplier|scrap|rework|use_as_is|accept_with_concession`) + `quality_capas` (number `CAPA-<seq>`, ncr_id, kind `corrective|preventive`, action_plan, owner_membership_id, due_on, status `open|in_progress|verified|closed`, verification_note) + `quality_defect_codes` (code UQ per tenant, name, category; seeded + tenant-defined)
- NCR creation paths: from failed inspections (inspection_id link), from shop-floor rejected qty at quality-gated steps (source `in_process`, auto-created by T-4A10-01), from customer complaints (manual, source `customer`)
- Disposition execution: `:dispose` (sensitive) drives the corresponding inventory movement (return-to-supplier, scrap issue, rework transfer, use-as-is release to sellable) via inventory's movement surface
- CAPA lifecycle: create → in_progress → verified → closed; verification by a membership ≠ owner (SoD); major/critical NCRs cannot close without ≥1 verified CAPA
- Events `quality.ncr.created` / `.disposed` / `.closed`, `quality.capa.created` / `.verified` / `.closed`

**Out of scope:**

- Inspection plans + gate mechanics — owned by [T-4A06-01](./T-4A06-01.md)
- Supplier corrective-action portals (supplier self-service) — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A06-02-1** — Disposition movement correctness: GIVEN an NCR with disposition `return_to_supplier` WHEN `:dispose` executes THEN the quarantined qty moves out via a return-to-supplier movement; `scrap` posts a scrap issue; `use_as_is` releases quarantine qty to sellable; each disposition's movement carries the NCR ref, and disposing without `quality:ncr:dispose` (sensitive, step-up) rejects.
2. **AC-T-4A06-02-2** — CAPA SoD holds: GIVEN a CAPA owned by membership M WHEN M attempts `:verify` THEN the request rejects with 403 `sod_conflict` + denial audit record; a different membership verifies successfully with a mandatory verification_note.
3. **AC-T-4A06-02-3** — Closure guard: GIVEN an NCR with severity `major|critical` and no verified CAPA WHEN `:close` is attempted THEN closure rejects with a named state error; after a CAPA reaches `verified`, closure succeeds; `minor` NCRs close without CAPA.
4. **AC-T-4A06-02-4** — Auto-creation seam: rejected qty reported at a quality-gated routing step (T-4A10-01) auto-creates an NCR with source `in_process` + subject ref to the work order/step — exactly one NCR per rejection report (idempotent on report ref).
5. **AC-T-4A06-02-5** — Defect codes are seeded + tenant-defined with codes UQ per tenant; NCR severity is immutable after creation except via audited correction; CAPA due_on drives overdue surfacing in the quality queue.
6. **AC-T-4A06-02-6** — Events `quality.ncr.created` / `.disposed` / `.closed` and `quality.capa.created` / `.verified` / `.closed` are emitted with refs (inspection, work order, supplier where applicable); rejection data feeds `supplier_performance` scoring inputs (T-4A03-04 consumes); payloads carry no amounts.
7. **AC-T-4A06-02-7** — GIVEN a principal lacking `quality:ncr:view` / `quality:ncr:create` / `quality:ncr:update` / `quality:ncr:dispose` / `quality:capa:view` / `quality:capa:create` / `quality:capa:update` / `quality:capa:verify` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
8. **AC-T-4A06-02-8** — Tenant isolation holds: every new table (`quality_ncrs`, `quality_capas`, `quality_defect_codes`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
9. **AC-T-4A06-02-9** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
