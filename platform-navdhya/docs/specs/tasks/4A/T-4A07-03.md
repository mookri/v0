## Objective

`products` gain `valuation_method` (`weighted_average|fifo`, additive, default `weighted_average`; standard costing reserved as a deferred seam). Weighted average keeps existing behavior (`inventory.valuation.changed` carries the new average). FIFO consumes `stock_valuation_layers` (variant_id, qty_remaining, unit_cost, received_ref, received_at) in receipt order: issue cost = Σ consumed layer qty × unit_cost; layers are append + decrement only (no edits). COGS posting consumes the issue cost from the movement payload (`cost_basis` additive field) — the posting engine stays valuation-agnostic. Changing valuation method on a variant with stock is prohibited (422 `inventory_valuation_change_blocked`). Stock aging reports `stock_levels` × batch/valuation layers in age buckets (0–30, 31–60, 61–90, 90+) by received date with value per bucket at current cost basis — served via `GET /api/v1/inventory/aging` and as a `finance_reports` definition.

## Scope

**In scope:**

- Additive `products.valuation_method` (`weighted_average|fifo`, default `weighted_average`; standard-costing value reserved)
- `stock_valuation_layers` (variant_id, qty_remaining, unit_cost, received_ref, received_at) — append + decrement only; FIFO issues consume layers in receipt order (issue cost = Σ consumed qty × unit_cost)
- Movement payload gains additive `cost_basis`; COGS posting consumes it (posting engine valuation-agnostic)
- Method-change guard: variant with stock ⇒ 422 `inventory_valuation_change_blocked` (re-valuation is a finance project, not a toggle)
- Stock aging: age buckets (0–30, 31–60, 61–90, 90+ days) by received date, value per bucket at current cost basis — `GET /api/v1/inventory/aging` (`inventory:stock:view`) + finance_reports definition (queued, org-scoped)

**Out of scope:**

- Standard costing (column value reserved; mechanics deferred) — owned by Deferred post-v1
- Re-valuation of existing stock between methods — owned by Finance project, not this task

## Acceptance criteria

1. **AC-T-4A07-03-1** — FIFO consumption order: GIVEN layers [10 @ 100, 10 @ 120] WHEN an issue of 15 executes THEN 10 units consume layer 1 (cost 1000) + 5 units consume layer 2 (cost 600) → issue cost 1600 on the movement's `cost_basis`; layer 2's `qty_remaining` decrements to 5; layers never edit historical unit_cost (append + decrement only, asserted by schema test).
2. **AC-T-4A07-03-2** — COGS posting is valuation-agnostic: the posting engine consumes `cost_basis` from the movement payload — GIVEN identical movements under weighted_average and fifo THEN the posting entries differ only in amount (no valuation-specific branches in the posting engine; architecture test).
3. **AC-T-4A07-03-3** — Method-change guard: GIVEN a variant with non-zero stock WHEN `valuation_method` is updated THEN the request rejects with 422 `inventory_valuation_change_blocked`; a zero-stock variant switches methods successfully (both paths feature-tested).
4. **AC-T-4A07-03-4** — Aging correctness: fixture receipts across the four age buckets produce the expected qty + value per bucket at current cost basis on `GET /api/v1/inventory/aging`; the same aggregation backs the finance_reports definition (queued, org-scoped artifact) — report output matches the API output for the same instant.
5. **AC-T-4A07-03-5** — `inventory.valuation.changed` carries the new cost for weighted-average variants and layer-consumption summaries for FIFO variants (additive fields); payloads carry cost basis + refs, never full ledger amounts.
6. **AC-T-4A07-03-6** — GIVEN a principal lacking `inventory:stock:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A07-03-7** — Tenant isolation holds: every new table (`stock_valuation_layers`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A07-03-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
