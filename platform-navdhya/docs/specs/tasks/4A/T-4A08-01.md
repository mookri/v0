## Objective

Feature-flagged channel adapter (behind `module.india_statutory`) that registers GST e-invoices asynchronously: on `invoicing.invoice.issued` for tenants with `india_statutory.einvoice_enabled` + turnover threshold met, the adapter composes the IRN payload (schema version pinned in adapter config) from invoice + customer GSTIN/address + line HSN (catalog) + tax-engine CGST/SGST/IGST split by place-of-supply, submits to the configured IRN endpoint (retries + circuit breaker), and stores `irn` + `irn_qr` (additive JSON on the invoice) with `einvoice_status=registered`; failure sets `einvoice_status=failed` + ops alert + retry queue. IRN never blocks invoice issuance (asynchronous by design). Cancellation within the statutory window is sensitive + audited. The tax engine stays jurisdiction-generic — statutory logic lives only in the adapter (ADR-0008).

## Scope

**In scope:**

- Trigger listener on `invoicing.invoice.issued` gated by tenant settings (`india_statutory.einvoice_enabled` + turnover threshold config)
- IRN payload composition: invoice + customer (GSTIN, address) + lines (HSN from catalog) + tax-engine output (CGST/SGST/IGST split by place-of-supply); schema version pinned in adapter config and recorded on each artifact
- Registration via channel adapter (retries + circuit breaker per integration-framework mechanics); success stores `irn` + `irn_qr` (additive JSON on invoice) + `einvoice_status=registered`; failure ⇒ `einvoice_status=failed` + ops alert + retry queue
- Asynchronous guarantee: IRN registration never blocks or rolls back invoice issuance
- Cancellation: `POST /invoices/{id}/einvoice:cancel` (within statutory window, `india_statutory:einvoice:cancel`, sensitive, audited) → adapter cancellation → `einvoice_status=cancelled`
- Adapter rules (shared with the whole package): provider endpoints are `channel_connections` configuration (never hard-coded); every call carries an idempotency key (invoice ref — retries never double-register); sandbox mode (`mode=sandbox`) returns deterministic mock registrations
- Events `india_statutory.einvoice.registered` / `.failed` / `.cancelled`

**Out of scope:**

- E-way bill generation (separate adapter) — owned by [T-4A08-02](./T-4A08-02.md)
- GSTR-1 export of registered IRNs (report layer consumes invoice state) — owned by [T-4A08-04](./T-4A08-04.md)
- Jurisdiction logic inside the tax engine — prohibited by ADR-0008 — owned by By design

## Acceptance criteria

1. **AC-T-4A08-01-1** — Async guarantee holds: GIVEN an invoice issued by an e-invoice-enabled tenant WHEN the IRN adapter is unreachable THEN the invoice issuance completes successfully with `einvoice_status=failed` + ops alert + a retry-queue entry — issuance is never blocked or rolled back by IRN state (fault-injection test).
2. **AC-T-4A08-01-2** — Payload correctness: the composed IRN payload matches the pinned schema-version fixture — GSTIN/address from the customer, HSN per line from catalog, CGST/SGST/IGST split from the tax engine by place-of-supply; the emitted schema version is recorded on the artifact (fixture test).
3. **AC-T-4A08-01-3** — Adapter rules: provider endpoint comes from `channel_connections` config (a test asserts no hard-coded endpoint in adapter code); every adapter call carries the invoice-ref idempotency key — replaying a registration retry never double-registers (mock-provider test); `mode=sandbox` returns deterministic mock IRNs for identical inputs.
4. **AC-T-4A08-01-4** — Cancellation guard: `POST /invoices/{id}/einvoice:cancel` requires `india_statutory:einvoice:cancel` with step-up (sensitive), succeeds only within the statutory window (out-of-window rejects with a named error), writes an audit record, and sets `einvoice_status=cancelled`.
5. **AC-T-4A08-01-5** — Events `india_statutory.einvoice.registered` / `.failed` / `.cancelled` are emitted with invoice ref + status (IRN value on registered); payloads carry no tax amounts — amounts stay on the invoice, refs in events.
6. **AC-T-4A08-01-6** — GIVEN a principal lacking `india_statutory:einvoice:view` / `india_statutory:einvoice:configure` / `india_statutory:einvoice:cancel` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A08-01-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
