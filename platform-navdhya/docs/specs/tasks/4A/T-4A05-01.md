## Objective

Employees capture expenses on a report model with category-driven receipt requirements: `expense_categories` (gl_account_key mapping, requires_receipt flag), `expense_reports` with a state machine (`draft|submitted|pending_approval|approved|rejected|reimbursed`), lines with Money amounts + receipt file refs, and a workflow approval chain with SoD (submitter cannot approve own report) and threshold escalation (second approver above tenant amount). Submitting a report with a missing required receipt rejects with 422 `expenses_receipt_required`; rejection returns to draft with note.

## Scope

**In scope:**

- `expense_categories` (code UQ per tenant, gl_account_key → `account_mappings`, requires_receipt bool, status) + `expense_reports` (number `EXP-<yyyy>-<seq>`, employee_id, org_id, status machine, trip_ref JSON NULL, currency, totals JSON) + `expense_report_lines` (category_id, occurred_on, amount Money, tax_amount NULL, description, receipt_file_id NULL, billable bool, customer_id NULL) + `expense_approvals` (approver_membership_id, decision, note, decided_at)
- Draft → submit: receipts required where `requires_receipt=true` (missing ⇒ 422 `expenses_receipt_required`); `:submit` freezes lines
- Workflow approval: reporting manager as default predicate; amount above tenant threshold escalates to a second approver; SoD — submitter cannot approve own report (approval_chain pattern, 403 `sod_conflict`)
- Rejection returns the report to `draft` with the rejection note
- Receipt upload via kernel Files under `expenses:report:update`; self-service `/me/expenses` surface (own-report scope)
- Events `expenses.report.created` / `.submitted` / `.approved` / `.rejected`, `expenses.approval.requested`, `expenses.line.flagged` (policy violation, e.g. duplicate receipt hash)

**Out of scope:**

- Reimbursement payout + GL posting — owned by [T-4A05-02](./T-4A05-02.md)
- Billable re-charge to projects (consumes this task's approval event) — owned by [T-4A05-02](./T-4A05-02.md)
- Corporate card feeds / OCR receipt capture — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A05-01-1** — Receipt enforcement holds: GIVEN a line on a category with `requires_receipt=true` and no `receipt_file_id` WHEN `:submit` is called THEN the request rejects with 422 `expenses_receipt_required`; with the receipt attached, submit succeeds and freezes the lines (post-submit edits reject).
2. **AC-T-4A05-01-2** — SoD holds on approval: GIVEN a report submitted by actor A WHEN A attempts `:approve` on it THEN the platform returns 403 `sod_conflict` with a denial audit record; a different approver with `expenses:report:approve` succeeds.
3. **AC-T-4A05-01-3** — Threshold escalation: reports above the tenant amount threshold require a second approver via the workflow machine; reports at/below threshold complete with a single approval (both paths feature-tested); rejection returns the report to `draft` carrying the note.
4. **AC-T-4A05-01-4** — Category configuration validates: `gl_account_key` must resolve against `account_mappings` (unknown keys reject at configure time), codes are UQ per tenant, and the duplicate-receipt-hash check flags lines (`expenses.line.flagged`) without blocking submission.
5. **AC-T-4A05-01-5** — Self-service scope: `/me/expenses` returns and mutates only the caller's own reports; staff endpoints with `expenses:report:*` operate across employees; receipt upload routes through kernel Files with size/type validation.
6. **AC-T-4A05-01-6** — Events `expenses.report.created` / `.submitted` / `.approved` / `.rejected`, `expenses.approval.requested`, and `expenses.line.flagged` are emitted with report/line refs; amounts stay out of event payloads (refs + totals only where needed).
7. **AC-T-4A05-01-7** — GIVEN a principal lacking `expenses:category:configure` / `expenses:report:view` / `expenses:report:create` / `expenses:report:update` / `expenses:report:approve` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
8. **AC-T-4A05-01-8** — Tenant isolation holds: every new table (`expense_categories`, `expense_reports`, `expense_report_lines`, `expense_approvals`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
9. **AC-T-4A05-01-9** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
