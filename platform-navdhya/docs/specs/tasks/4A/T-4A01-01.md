## Objective

CRM captures and qualifies leads on its own state machine (`new → contacted → qualified → converted`, plus `discarded` with mandatory reason) and converts them without ever writing customers or sales tables directly: conversion resolves an existing customer via `CustomerLookup` or creates one through the customers module's new `CustomerCreator` contract, optionally opens an opportunity, and drafts a quote through sales' new `QuoteDraftFactory` contract — each flag-driven, idempotent, and event-emitting.

## Scope

**In scope:**

- `crm_leads` entity (number `LEAD-<seq>`, source, campaign_id, owner, score, status machine) + lead CRUD endpoints under `/api/v1/crm`
- Lead state machine with `discarded` mandatory reason; `:convert` as the only path to `converted`
- Conversion flow: customer resolution/creation via `CustomerCreator`, optional opportunity (`with_opportunity`), optional draft quote via `QuoteDraftFactory` (`with_quote`)
- Idempotent conversion (duplicate conversion replays stored result); activities copied by reference

**Out of scope:**

- Opportunity + pipeline machinery — owned by [T-4A01-02](./T-4A01-02.md)
- Campaign entities beyond the lead's campaign_id reference — owned by [T-4A01-03](./T-4A01-03.md)
- Direct CRM writes into customers/sales tables — prohibited by architecture test — owned by By design

## Acceptance criteria

1. **AC-T-4A01-01-1** — Conversion guards hold: GIVEN a lead not in `qualified` WHEN `:convert` is called THEN the request rejects with a named state error; GIVEN a qualified lead WHEN converted with `with_opportunity=true` and `with_quote=true` THEN a customer exists (linked or created via `CustomerCreator`), an opportunity carries `lead_id` + `campaign_id`, and a draft quote is pre-filled from the lead's item list via `QuoteDraftFactory`.
2. **AC-T-4A01-01-2** — CRM never writes customers/sales tables directly: the architecture test asserts CRM's write surface is limited to `crm_*` tables and cross-module effects happen exclusively through the published contracts.
3. **AC-T-4A01-01-3** — `POST /api/v1/crm/leads/{id}:convert` is idempotent: replaying the conversion returns the stored result (same customer/opportunity/quote ids) without creating duplicates.
4. **AC-T-4A01-01-4** — Events `crm.lead.created` / `.updated` / `.qualified` / `.converted` / `.discarded` are emitted with lead references; `.converted` carries customer_id, opportunity_id, quote_id; `.discarded` carries the mandatory reason.
5. **AC-T-4A01-01-5** — GIVEN a principal lacking `crm:lead:view` / `crm:lead:create` / `crm:lead:update` / `crm:lead:convert` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-4A01-01-6** — Tenant isolation holds: every new table (`crm_leads`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-4A01-01-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
