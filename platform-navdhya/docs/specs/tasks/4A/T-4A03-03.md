## Objective

Inbound logistics charges are allocated to received goods in the same transaction as the GRN posting, raising item cost basis and ledger value: `goods_receipt_landed_costs` rows per GRN carry component (`freight|duty|insurance|customs|misc`), amount, and allocation rule (`by_value|by_qty|by_weight`); each accepted line receives its share, `inventory.valuation.changed` carries `landed=true` + component breakdown (additive fields), and the posting engine books landed components to the inventory asset account against landed-cost clearing / AP accrual per `account_mappings`. Editing landed costs after bill-match is prohibited — late charges go through revaluation entries.

## Scope

**In scope:**

- `goods_receipt_landed_costs` (per GRN): `component` (`freight|duty|insurance|customs|misc`), `amount` (Money), `allocation` (`by_value|by_qty|by_weight`), `supplier_ref NULL` (e.g. carrier bill)
- Allocation at GRN posting — same transaction as the receipt movements; per-line landed cost ÷ qty raises the item's cost basis
- `inventory.valuation.changed` carries `landed=true` + component breakdown (additive fields on the existing event)
- GL via posting engine: landed components → inventory asset account (credit: landed-cost clearing / AP accrual per component mapping in `account_mappings`)
- Edit prohibition after GRN bill-match; late charges route through revaluation entries (GL reversal pattern)

**Out of scope:**

- Landed cost on non-GRN inbound flows (transfers, returns) — owned by By design
- Automatic carrier-invoice ingestion (supplier_ref is manual in v1) — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A03-03-1** — Allocation atomicity holds: landed cost allocation executes in the same transaction as the GRN receipt movements — GIVEN a GRN with two landed components WHEN posting THEN receipt movements, cost-basis updates, and GL postings all commit together or not at all (fault-injection test asserts no partial state).
2. **AC-T-4A03-03-2** — Allocation correctness per rule: GIVEN a GRN with lines of differing value/qty/weight WHEN landed costs allocate `by_value`, `by_qty`, and `by_weight` respectively THEN each line's share matches the rule's ratio (rounding remainder lands on the last line), and the resulting `inventory.valuation.changed` events carry `landed=true` with the component breakdown.
3. **AC-T-4A03-03-3** — GL correctness: landed components post to the inventory asset account with credits to landed-cost clearing / AP accrual per the component's `account_mappings` entry; postings are balanced and valuation-agnostic (posting engine consumes the movement payload).
4. **AC-T-4A03-03-4** — Edit prohibition after bill-match: GIVEN a GRN that is bill-matched WHEN a landed cost edit is attempted THEN the request rejects with a named 422 error; the documented late-charge path (revaluation entry per the GL reversal pattern) succeeds instead.
5. **AC-T-4A03-03-5** — Event `purchasing.landed_cost.applied` is emitted with GRN ref + component summary (amounts stay in the ledger; event carries refs and component kinds); the event never fires for allocations that rolled back.
6. **AC-T-4A03-03-6** — GIVEN a principal lacking `purchasing:landed_cost:create` / `purchasing:landed_cost:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
7. **AC-T-4A03-03-7** — Tenant isolation holds: every new table (`goods_receipt_landed_costs`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
8. **AC-T-4A03-03-8** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
