## Objective

Users switch Working Context through an explicit API + UX contract: a switch endpoint bounded by MaximumAuthority, context stack push/pop for nested operations, and the switcher/stack/default UX rules (EXP-011…013). The existing org tree migrates backward-compatibly to hierarchy type `organization` with an id-mapping table, preserving org-scope ABAC behavior exactly.

## Scope

**In scope:**

- Context switch endpoint + audit; context stack storage + bounded depth
- Org-tree migration: `organization` hierarchy, `org_id` → node mapping table, ABAC regression proof
- Switcher UX contract implementation in the Blade admin spine (authorized nodes only)

**Out of scope:**

- Per-domain business meaning of scope modes (each domain defines it in its own file) — owned by Domain files under 14-domains/
- Buyer/POS panel context UX (panel-specific wiring follows EXP defaults) — owned by Phase 2 surfaces

## Acceptance criteria

1. **AC-T-0K02-03-1** — Endpoint `POST /api/v1/context/switch` switches the persisted Working Context to an authorized node and returns the resolved context; switching to a node outside MaximumAuthority returns 403 with envelope code `forged_context_denied`.
2. **AC-T-0K02-03-2** — Context stack push/pop semantics hold: nested operations push a temporary context and pop back to the prior one, stack depth is bounded, and every switch/push/pop writes an audit record.
3. **AC-T-0K02-03-3** — The org-tree migration converts the existing tree to hierarchy type `organization`: every legacy `org_id` resolves through the id→node mapping table, and the org-scope ABAC regression suite passes unchanged after migration (HIER-015 backward-compatibility proof).
4. **AC-T-0K02-03-4** — The Working Context switcher lists only nodes within the principal's MaximumAuthority; navigation and context-scoped defaults re-render after a switch (EXP-011/012/013) — verified by feature tests on the Blade admin spine.
5. **AC-T-0K02-03-5** — GIVEN a principal lacking `platform:context:switch` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-0K02-03-6** — Tenant isolation holds: every new table (`context_stack_entries`, `hierarchy_node_id_map`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-0K02-03-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
