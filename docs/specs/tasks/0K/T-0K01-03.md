## Objective

Every authorization decision is logged with principal, capability, resource, working context, decision, deciding stage, and evaluated policies — sampled-allow / full-deny. AI-agent principals (service principal kind `agent`) are constrained: sensitive capabilities require a human-in-the-loop approval token, agent scopes are budgeted, and every agent denial is flagged for anomaly review.

## Scope

**In scope:**

- Decision log table + writer (sampled allow, full deny) with deciding-stage attribution
- AI-agent safety rules in the evaluation chain (agent kind detection, sensitive-action gate, budget checks)
- Restricted decision-log query API + anomaly flag emission
- Retention + redaction rules for log payloads

**Out of scope:**

- Anomaly detection models (intelligence layer consumes the flags) — owned by Intelligence roadmap (P6)
- Changes to the precedence chain itself — owned by [T-0K01-02](./T-0K01-02.md)

## Acceptance criteria

1. **AC-T-0K01-03-1** — Every DENY decision is logged in full (principal, capability, resource, working context, deciding stage, evaluated policies); allow decisions are logged at the configured sample rate and the sampling config change is audited.
2. **AC-T-0K01-03-2** — GIVEN an AI-agent principal requesting a capability flagged `sensitive` WHEN evaluated THEN the decision is DENY with deciding stage `agent_safety` unless a human-in-the-loop approval token is presented with the request.
3. **AC-T-0K01-03-3** — Endpoint `GET /api/v1/authz/decisions` returns paginated decision records filtered by principal/capability/outcome for holders of `platform:decision_log:view` and 403 otherwise.
4. **AC-T-0K01-03-4** — Event `platform.authz.anomaly_flag` is emitted when an agent's denial rate crosses the configured threshold, with the agent principal + window in the payload.
5. **AC-T-0K01-03-5** — GIVEN a principal lacking `platform:decision_log:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-0K01-03-6** — Tenant isolation holds: every new table (`authz_decision_log`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-0K01-03-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
