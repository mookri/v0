## Objective

Declarative quality gates across inbound/in-process/outbound flows: `quality_inspection_plans` define gate (`inbound|in_process|outbound`), trigger matchers (variant/category/supplier + sampling rule), and checks (`pass_fail|measure` with spec + uom). Inbound: GRN posting matches active plans and routes received qty to a `quarantine` location without blocking the GRN — the gate controls the move to sellable. Inspection decisions (`:pass` moves quarantine → sellable via transfer with `ref_type=quality_inspection`; `:fail` routes qty per NCR disposition; `:waive` is sensitive, ACR 2 + reason). In-process: routing steps flagged `quality_gate=true` require a passed inspection before the next operation may report completion (422 `manufacturing_gate_not_cleared`). Outbound: return-receipt inspections feed quarantine dispositions. Quality never blocks writes synchronously except at declared gates (event-driven gates per ADR-0010).

## Scope

**In scope:**

- `quality_inspection_plans` (code UQ per tenant, gate `inbound|in_process|outbound`, trigger JSON {variant_ids/category_ids/supplier_ids, sampling_rule}, checks JSON [{name, kind: pass_fail|measure, spec, uom}], status) + `quality_inspections` (number `QC-<seq>`, plan_code, gate, subject_type `goods_receipt|work_order|return_receipt`, subject_id, status `pending|in_progress|passed|failed|waived`, inspected_by, decided_at, result JSON)
- Inbound gate: GRN posting checks active `inbound` plans matching (variant/category/supplier); match ⇒ received qty lands in `quarantine` location + inspection created; GRN is NOT blocked — the gate controls the move to sellable
- Inspection decisions: `:pass` transfers quarantine qty → sellable (`ref_type=quality_inspection`); `:fail` routes qty per NCR disposition; `:waive` requires `quality:inspection:waive` (sensitive, ACR 2) + reason
- In-process gate: routing steps gain additive `quality_gate` flag; the next operation's completion report is rejected with 422 `manufacturing_gate_not_cleared` until the gate's inspection passes (state consumed by shop-floor reporting, T-4A10-01)
- Outbound gate: return receipt inspection trigger; disposition `quarantine` lines flow into quality
- Events `quality.inspection.created` / `.passed` / `.failed` / `.waived`

**Out of scope:**

- NCR + CAPA machinery (created by failed inspections, managed separately) — owned by [T-4A06-02](./T-4A06-02.md)
- Statistical process control / sampling analytics — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-4A06-01-1** — Inbound gate flow: GIVEN an active inbound plan matching (variant, supplier) WHEN a GRN posts THEN the GRN is NOT blocked, received qty lands in a `quarantine` location, sellable stock is unchanged, and an inspection is created; GIVEN no matching plan THEN qty lands sellable directly.
2. **AC-T-4A06-01-2** — Decision effects hold: `:pass` moves the quarantine qty to sellable via an inventory transfer with `ref_type=quality_inspection`; `:fail` routes qty per the linked NCR disposition; `:waive` requires `quality:inspection:waive` with step-up (ACR 2) + a mandatory reason, and is audited.
3. **AC-T-4A06-01-3** — In-process gate: GIVEN a routing step flagged `quality_gate=true` without a passed inspection WHEN the next operation reports completion THEN the request rejects with 422 `manufacturing_gate_not_cleared`; after the inspection passes, the same report succeeds (gate state exposed via quality's query surface).
4. **AC-T-4A06-01-4** — Event-driven gating per ADR-0010: quality hooks run on purchasing/returns/manufacturing events (not synchronous writes into those modules' transactions) — the architecture test asserts quality never registers synchronous write observers on other modules' aggregates; only declared gate checks (GRN match, gate-state query) couple the flows.
5. **AC-T-4A06-01-5** — Plan configuration validates: trigger matchers reference existing variants/categories/suppliers (unknown refs reject at configure time), checks with `kind=measure` require spec + uom, and plan codes are UQ per tenant; plan configure is sensitive (step-up).
6. **AC-T-4A06-01-6** — Events `quality.inspection.created` / `.passed` / `.failed` / `.waived` are emitted with inspection + subject refs and per-check outcome summary; `.waived` carries the mandatory reason; payloads carry no amounts.
7. **AC-T-4A06-01-7** — GIVEN a principal lacking `quality:plan:configure` / `quality:inspection:view` / `quality:inspection:decide` / `quality:inspection:waive` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
8. **AC-T-4A06-01-8** — Tenant isolation holds: every new table (`quality_inspection_plans`, `quality_inspections`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
9. **AC-T-4A06-01-9** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
