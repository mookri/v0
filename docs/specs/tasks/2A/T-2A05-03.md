## Objective

Storefront content aggregates are managed and served headless: pages and blogs/articles with sanitized HTML bodies, scheduled publishing (`published_at` future = scheduled job), SEO metadata, and acyclic navigation menus served as ordered JSON. Published content enters sitemaps (T-2A11-02) and is readable on the public storefront API.

## Scope

**In scope:**

- `content_pages`, `content_blogs`, `content_articles` with sanitized `body_html`, template hints, SEO JSON, scheduled publish
- `content_menus` + `content_menu_items` (validated acyclic, ordered, typed link targets)
- Admin CRUD + `:publish` endpoints; public read endpoints on the allowlist
- HTML sanitization per the ecosystem allowlist rules

**Out of scope:**

- Theme rendering (storefront consumes JSON headlessly) — owned by ADR-0015
- Content versioning/rollback — owned by Deferred post-v1

## Acceptance criteria

1. **AC-T-2A05-03-1** — HTML sanitization strips disallowed elements/attributes per the ecosystem allowlist before persistence; stored bodies re-render unchanged through the sanitizer (idempotent sanitization test).
2. **AC-T-2A05-03-2** — Scheduled publishing holds: a page/article with future `published_at` is invisible on public surfaces until the scheduler flips it live, and appears in sitemaps only after publication.
3. **AC-T-2A05-03-3** — Menu trees are validated acyclic on write; cycle-creating updates reject with a named code, and the storefront API returns items in stored order.
4. **AC-T-2A05-03-4** — Events `content.page.published` / `.unpublished`, `content.article.published` / `.unpublished`, and `content.menu.updated` are emitted with store + handle references.
5. **AC-T-2A05-03-5** — GIVEN a principal lacking `content:page:view` / `content:page:create` / `content:page:update` / `content:article:view` / `content:menu:view` / `content:menu:create` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A05-03-6** — Tenant isolation holds: every new table (`content_pages`, `content_blogs`, `content_articles`, `content_menus`, `content_menu_items`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A05-03-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
