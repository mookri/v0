## Objective

Buyers see their order history and can reorder: a `buyer_order_views` read model is built from `sales.*` / `checkout.order.placed` events (no cross-module joins), the history endpoint serves it with status snapshots, and reorder creates a new cart from a past order's lines with current-price re-resolution and stock re-validation.

## Scope

**In scope:**

- `buyer_order_views` event-driven read model + refresh listeners (debounced, idempotent)
- History endpoint (pagination, status snapshots) under the buyer surface
- Reorder flow: cart creation from past lines, price re-resolution, unavailable-line handling

**Out of scope:**

- Returns/refund initiation from history (returns module surface) — owned by Phase 2 returns baseline
- Invoice/document downloads — owned by Phase 1 invoicing surface

## Acceptance criteria

1. **AC-T-2A04-02-1** — The order history read model is event-built: listeners consume `sales.*`/`checkout.order.placed`, and the architecture test asserts no cross-module joins in the listener's query surface (ADR-0011).
2. **AC-T-2A04-02-2** — Reorder creates a cart with the past order's lines re-resolved at current prices; lines that no longer exist or are unavailable are reported in the response and skipped, never silently substituted.
3. **AC-T-2A04-02-3** — `GET /customer-accounts/orders` returns only orders belonging to the caller's buyer profile (buyer-scoped), paginated, with status snapshots from the read model.
4. **AC-T-2A04-02-4** — Event `customer_accounts.order.reordered` is emitted with source order + new cart references.
5. **AC-T-2A04-02-5** — GIVEN a principal lacking `customer_accounts:profile:view` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A04-02-6** — Tenant isolation holds: every new table (`buyer_order_views`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A04-02-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
