## Objective

One catalog sells at per-market prices: `MarketPriceResolver` resolves a variant's price for a market with deterministic precedence (fixed variant rule > multiplier > market-wide rule > FX-derived from the base price list), recording the FX rate used. Resolved prices materialize into `market_price_projections` as an eventual read model that is never the price of record; stale projections are flagged and recomputed on upstream price or rule changes.

## Scope

**In scope:**

- `MarketPriceResolver.resolve(market_id, variant_id, ctx)` with the four-level precedence chain
- Projection writer consuming `markets.price_rule.updated` and catalog/price-list change events
- FX rate snapshot per projection row (`fx_rate_used`, `computed_at`)
- Staleness detection emitting `markets.projection.stale`

**Out of scope:**

- Duty amounts and tax display (price resolution feeds them but does not compute them) — owned by [T-2A01-03](./T-2A01-03.md)
- Base price lists themselves (Phase 1 pricing) — owned by Phase 1 pricing baseline

## Acceptance criteria

1. **AC-T-2A01-02-1** — Price resolution precedence holds: GIVEN a fixed variant rule, a multiplier rule, and a market-wide rule for the same variant WHEN resolved THEN the fixed variant rule wins; removing it falls through to multiplier, then market-wide, then FX-derived base price (ADR-0007 overlay semantics).
2. **AC-T-2A01-02-2** — Every resolved price records `fx_rate_used` + `computed_at`; FX-derived prices recompute deterministically for a given rate snapshot (no hidden live-rate reads).
3. **AC-T-2A01-02-3** — Event `markets.projection.stale` (market_id, variant_id) is emitted when an upstream price list or price rule change invalidates a projection, and the projection writer refreshes it within the relay window.
4. **AC-T-2A01-02-4** — `market_price_projections` is an eventual read model: checkout/storefront price-of-record reads go through `MarketPriceResolver`, never directly off the projection (architecture-tested consumer list).
5. **AC-T-2A01-02-5** — GIVEN a principal lacking `markets:price_rule:view` / `markets:price_rule:create` / `markets:price_rule:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
6. **AC-T-2A01-02-6** — Tenant isolation holds: every new table (`market_price_rules`, `market_price_projections`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
7. **AC-T-2A01-02-7** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
