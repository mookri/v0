## Objective

The markets module exists as a first-class module: manifest, provider, routes registered, test directories, and the five core entities (markets, market_channels, market_price_rules, market_duty_rates, market_price_projections) with lifecycle management. A market is a sellable region segment composing currency, countries, duty mode, and tax display — the structural base for market pricing and duties.

## Scope

**In scope:**

- Module scaffold: directory, `module.json` manifest (permissions, events, navigation), provider, route registration, test layout
- Migrations for `markets`, `market_channels`, `market_price_rules`, `market_duty_rates`, `market_price_projections`
- Market CRUD + lifecycle (`active|paused`) endpoints under `/api/v1/markets`
- Market code uniqueness per tenant; soft delete; countries/tax_display/rounding/duty_mode columns per the domain register

**Out of scope:**

- Market price resolution + projections — owned by [T-2A01-02](./T-2A01-02.md)
- Duties at checkout + tax display enforcement — owned by [T-2A01-03](./T-2A01-03.md)
- Channel wiring beyond the `market_channels` association table — owned by P2-Commerce store baseline

## Acceptance criteria

1. **AC-T-2A01-01-1** — The five market tables exist with the registered column sets; `markets.code` is unique per tenant, lifecycle is `active|paused`, and soft delete is enforced (no hard deletes of markets).
2. **AC-T-2A01-01-2** — Endpoint `POST /api/v1/markets` returns 201 with the market envelope for a valid payload and 422 with `validation_failed` for duplicate code, unknown currency, or invalid `duty_mode`/`tax_display` values.
3. **AC-T-2A01-01-3** — Events `markets.market.created` / `.updated` / `.paused` / `.activated` are emitted with the market payload and correlation ids on each lifecycle transition.
4. **AC-T-2A01-01-4** — GIVEN a principal lacking `markets:market:view` / `markets:market:create` / `markets:market:update` WHEN the corresponding request is issued THEN the platform returns 403 with envelope code `authorization_denied` and writes a denial audit record (negative path).
5. **AC-T-2A01-01-5** — Tenant isolation holds: every new table (`markets`, `market_channels`, `market_price_rules`, `market_duty_rates`, `market_price_projections`) is covered by the `AssertTenantIsolation` matrix — cross-tenant reads return no rows and unresolvable tenant contexts fail closed (enforced by the [Tenant Isolation Suite (standing)](../../../19-testing/testing-strategy.md#tenant-isolation-suite-standing)).
6. **AC-T-2A01-01-6** — The module manifest declares every permission, event, and navigation entry introduced by this task; `platform:sync-permissions` and `module:list` reflect them, and every state change introduced writes an audit record (DoD items 3 + 5).
